# 平台部署、商业授权与运维

适用范围：v2 候选隔离验证及批准后部署。实际单店停写、两份备份和 91 人期初按 [一次性切换](relational-refactor-assessment.md#8-一次性切换流程) 执行；本轮未执行清库、卸载或部署。

## 初始化空目标

按 [部署说明](../deploy/README.md#首次启动) 准备独立 PostgreSQL 和新空库。初始化首位平台管理员，再创建门店和初始店主。新门店默认未授权，先根据实际合同签发明确的期限、功能和离线小时数，再测试商家入口及目标设备；旧会话不迁入新账本。

首位平台管理员只能通过 CLI 创建一次，没有公开注册接口。使用迁移/运维数据库凭据运行初始化命令。不要将密码写进镜像、Git 或命令参数历史：

~~~sh
read -r -p '平台账号：' PLATFORM_ADMIN_USERNAME
read -r -s -p '平台密码（至少12位）：' PLATFORM_ADMIN_PASSWORD
printf '\n'
export PLATFORM_ADMIN_USERNAME PLATFORM_ADMIN_PASSWORD
docker compose run --rm --no-deps -e PLATFORM_ADMIN_USERNAME -e PLATFORM_ADMIN_PASSWORD migrate node server/create-platform-admin.js
unset PLATFORM_ADMIN_USERNAME PLATFORM_ADMIN_PASSWORD
~~~

访问 /admin/platform.html 登录。创建门店与初始店主，然后配置授权。已有店主初始化命令仍可使用，但创建的门店默认未授权。平台超级管理员可添加运营、开发者、审计员；不能禁用或降级最后一位在用超级管理员。

## 在线商业授权

在“门店与商业授权”中查询并选择门店：

- “按天授权”在签发/续期时以服务器当前 UTC 时间计算到期时间；1 天为 86400 秒。续期操作从当前时间重新计算，不自动累加旧剩余天数。
- “永久授权”无商业到期日期，但依然要求登录，且可由平台停用或调整功能。
- 最长离线小时数为 0 时要求在线。非零时，实际租期为平台上限、店主设备上限、门店到期日、设备到期日的交集。
- “保存功能与状态”保留原来的起止日期；“签发/续期”才重新计算期限。并发修改须提交当前版本，冲突返回 409，不能静默覆盖。
- 平台禁用用户独立于商家停用。店主启用其员工不能解除平台禁用；角色、禁用或重置密码后撤销该用户所有在线会话。
- 服务端每次受保护请求及业务事务重新校验授权。已断网且持有有效租期的设备，只能在租期到期或恢复连接时得知远程变化；联网终端每 30 秒心跳，连接确认窗口最长 60 秒。紧急终止不能撤回已经离线交付的数据。

原生在线凭据仍使用现有安全存储与持久登录机制；商业许可证不代替用户权限。网页不支持离线资金写入。报表/导出按钮的限制属于产品功能控制：获得合法账本读取权的用户已拥有相应数据，无法依靠隐藏按钮阻止其自行复制。

## 独立离线授权

### 密钥准备

在可信的运维环境中，进入完整源码检出目录后运行一次（精简 API 容器不包含密钥生成脚本）：

~~~sh
npm run license:keys -- .license-keys main
~~~

生成 main.private.pem 和 main.public.json；命令拒绝覆盖已有密钥。私钥必须只在平台签发端保存，做好加密离线备份并限制文件权限。不要放入 App、网页、日志、普通备份或公开下载目录。默认目录和私钥文件名已加入 Git 忽略规则；仍应检查自定义路径。

将 public.json 的完整 JSON 内容注入 App 构建环境 VITE_LICENSE_PUBLIC_KEYS，再运行 build:web 和原生同步/构建。公钥是公开信息，可包含多个 keyId 以支持轮换。没有受信公钥的 App 会拒绝离线码，不能用授权码自带公钥绕过。

服务端设置 LICENSE_PRIVATE_KEY_FILE 和 LICENSE_KEY_ID。Docker 可叠加密钥挂载配置：

~~~sh
docker compose -f compose.yaml -f deploy/compose.licensing.yaml up -d --build
~~~

.env 中设置 LICENSE_PRIVATE_KEY_HOST_FILE 为主机私钥绝对路径，VITE_LICENSE_PUBLIC_KEYS 为公钥 JSON。确保容器 node 用户可读该文件，且其他用户不可读；Compose 本地文件型 secret 的 uid/mode 支持因运行环境而异，应验证实际权限。不要把 .license-keys 目录传进构建上下文（.dockerignore 已排除）。

deploy/deploy-update.sh 检测到已配置 LICENSE_PRIVATE_KEY_HOST_FILE 时，会同时加载授权密钥挂载和适用的 IP 证书配置；缺少授权配置文件时停止升级，防止重建容器后丢失签发能力。导出的同名环境变量优先于 .env，与 Compose 一致；脚本不执行 .env，也不打印私钥内容或路径。

轮换时先向 App 发布含新旧公钥的版本，再切换签发端 keyId 和私钥。删除旧公钥将使旧离线码无法在该新版客户端验签，必须按合同安排换码；完全断网的旧 App 不会自动更新公钥或收到撤销。私钥泄露应停止签发、轮换密钥、升级终端和重新交付授权。

### 交付流程

1. 商家安装新版 App，在登录页展开“离线商业授权与本地登录”，复制设备标识。
2. 平台选择对应门店，输入设备标识、本地账号、姓名、授权天数或永久、开放功能。离线模式不提供云端语音、员工及设备管理。
3. 点击签发，把完整授权码安全交付到该设备。授权从签发时间开始计算，不从首次输入时开始，避免重装后重新计时。
4. 商家在 App 输入授权码，设置并确认至少 12 位本地密码，确认账本归属后激活。激活同时完成首次本地登录，后续可用本地账号密码重新登录。
5. 本地安全存储保存签名码、PBKDF2-SHA256 密码摘要和时间水位；不保存明文密码。不上传本地账本，不产生云端待同步操作。App 重启可恢复安全存储内的有效会话；主动退出会隐藏账本并阻止写入。
6. 同设备续期时重新签发并导入新码。密码遗忘可由持有有效码的授权管理员重新激活并设置新密码。跨门店不能直接覆盖现有账本；云端绑定或未同步待办须先处理，避免混账。

服务端保存签发内容和授权码摘要，审计不记录完整授权码或密码。签发页面关闭后不能通过摘要还原原码，服务商应安全交付并另行保管；重新签发不会自动使此前已交付的离线码失效。离线码绑定设备，不能用于另一台设备；更换设备应重新办理授权与账本迁移。

纯离线许可不能做到可靠远程撤销，也无法完全抵御 Root、程序篡改、回滚整机存储或不可信系统时钟。当前实现检测常见回拨并保留单调时间水位，不宣称具备硬件可信计时。对此有硬性要求的合同应采用在线授权且离线小时数为 0，或配套可信硬件。

## 日志与性能

平台/门店审计是关系表，资金及管理变更与对应业务事务一起提交，数据库失败时该变更失败，不丢失关键审计。门店连接记录沿用客户端积攒后批量发送，队列最多 256 条，重复相邻连接状态不再累积。

API 请求诊断不额外发 HTTP 日志请求。每 API 实例有 2000 条等待队列，每 2 秒最多批量写 100 条；成功请求采样 1%，错误请求尝试全量入队。队列满或数据库不可用时丢弃诊断并累加 dropped 指标，进程崩溃时内存诊断也可能丢失。平台“运行状态”显示当前实例队列、写入和丢弃计数，不代表整个集群。每 15 分钟最多清理 1000 条超过 7 天的诊断，因此持续高错误流量下还应配置 DBA 分区/保留作业与磁盘告警。

日志不保存请求体、密码、Bearer、完整授权码或原始查询串；路由中动态标识被归一化。平台查询使用 id 游标、每页最多 100 条；界面默认 50 条，无持续轮询和大 OFFSET。诊断不是零开销；上线必须测量队列、DB I/O 和 p95/p99 延迟，按业务峰值配置容量。

平台审计和资金审计不自动删除。需按合同和审计要求归档后，由专用维护身份清理；API 数据库角色没有修改/删除这两类审计记录的权限。不要让日志清理作业删除 ledger_command_receipts、application_task_receipts、恢复或批次回执；客户端会按原号查证和重试。

## 安全、监控与恢复

- 对外只开放 HTTPS 反向代理，生产 API 使用受限 member_app 数据库账号；迁移身份与运行身份分开。平台控制台建议额外放在 VPN、IP 白名单或身份代理后，并在身份代理启用 MFA。当前应用内平台登录为密码认证，不包含内建 MFA。
- 平台令牌与商家令牌分表，存数据库摘要；平台令牌绝对有效期 8 小时，界面闲置 15 分钟退出。平台令牌存当前标签页 sessionStorage，不写入商家会话键。密码/角色变更撤销旧平台会话。
- 配置 DB_POOL_MAX（默认 10，允许 1–100）、DB_CONNECT_TIMEOUT_MS（默认 5000）、DB_STATEMENT_TIMEOUT_MS（默认 15000）；lock_timeout=5000、idle_in_transaction_session_timeout=30000。总连接数乘以 API 副本数，避免耗尽数据库。
- /api/health 只表示进程存活；/api/ready 检查数据库可用性，不证明复制、备份或所有外部语音服务正常。连接池故障和请求错误使用代码与请求 ID 定位，响应不返回数据库内部消息。
- 定期独立验证备份、账户版本及余额、命令回执、授权、平台账号和密钥。授权不随业务归档恢复；业务恢复必须同店空目标和独立恢复角色并产生新代际，旧手机按 [原单与恢复处置](refactor-implementation.md#原单与恢复处置) 核对。严禁直接开放回退物理库给仍用同代际的设备。
- 默认 compose 不是高可用。多实例、数据库主备、负载均衡、热备、RPO/RTO 和分库路线详见架构文档。没有做过故障演练就不能承诺自动容灾或零丢失。
