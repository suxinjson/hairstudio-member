# 全量重构专项测试与发布门槛

更新日期：2026-11-20。本文是发布合同，实际验证与缺口以 [实施台账](refactor-implementation.md) 为准。范围为单店 91 位会员关键档案及剩余余额；在线使用新 PostgreSQL，Android 使用 SQLite，不沿用旧账本协议。**当前候选版禁止发布及营业切换。**

## 1. 执行原则与证据

- 测试覆盖解耦、功能、资金正确性和性能四个维度；任何一个未完成，都不能称重构完成。
- 单元测试可用替身；事务、SQL 约束、锁竞争和连接池必须用真实 PostgreSQL 多连接验证，本地资金必须覆盖真实 SQLite 及 Android 运行路径。
- 真实 91 人数据只用于隔离、受控的导入核对，不进入代码、通用压力数据集或公开报告。压测使用确定性生成的合成数据。
- 禁止将并发、清库、故障注入或安全扫描指向生产；测试使用专用数据库、账号、设备和可丢弃环境。
- 每次输出构建/源码摘要、环境、数据库与依赖版本、随机种子、请求数、并发、耗时、通过/失败/跳过、逐项断言及残留风险。
- 关键项不得跳过。需要真实数据库、JDK 或设备但环境缺失时，标记“未验证，阻止发布”，不能用 PGlite 或网页构建成功替代。
- 现有 704 项基线属于旧版本。迁移其仍有效的安全和业务断言；旧快照、旧协议兼容测试随旧路径删除，不保留两套资金实现。

报告放在 `output/refactor-v2/<run-id>/`。允许同一源码摘要使用实库、桌面 SQLite、Linux 和 Android 分别取证；任何失败、跳过、环境不匹配都单独记录。改变资金、同步、权限、数据库模型、镜像或安装包须复验受影响阶段。真实会员文件、逐人明细、密钥和连接密码不进入产物目录。

当前候选 Temurin JDK 21 下 Windows 全量回归 466 项，465 通过、0 失败、1 项平台不支持的 `flock` 跳过；对应锁并发用例在 WSL 单项复跑 1/1。另从锁定交付包在干净 Ubuntu 24.04/WSL2 环境安装 Linux 依赖后复跑 deployment 套件 17/17，零失败、零跳过，源码摘要保持不变；此前共享 Windows `node_modules` 下的 Rollup 缺包失败作为已解决的环境问题保留原始记录。[全量日志与结构化报告](../output/refactor-v2/validation-20261120/regression-jdk21-resume-20261120.json)及[干净 Linux 复跑报告](../output/refactor-v2/validation-20261120/deployment-clean-wsl-648f6c5.json)。本地核心复验 198/198、真实 PostgreSQL 120/120，零失败、取消或跳过；新只读 HTTPS 演练通过。已定位并修复重复恢复上传提前关闭连接的问题，新增延迟分块、空闲/总时限、取消和容量边界回归。PG 十万笔、百万笔归档恢复、20 店基线隔离，以及 [PostgreSQL 进程故障](../output/refactor-v2/validation-20261120/process-faults-final/summary.json) 和 [SQLite 进程/资源故障](../output/refactor-v2/validation-20261120/sqlite-process-faults/summary.json) 报告来自 `f74a8f2` 候选；相对该版仅修改 HTTP 上传收尾、对应测试与平台说明，归档服务、数据库和 SQLite 实现未变，按范围保留原摘要证据。文件 SQLite 与真实 PostgreSQL 的扩展随机事务各通过 200,000 步，完整适用范围见 [实施台账](refactor-implementation.md#验证命令与当前证据)。后台已重新构建；Android Debug 构建、签名检查及 6 项 JVM 单测证据继续保留。当前摘要在 API 24 Android 7.0 x86_64 仿真器上另跑 connected instrumentation 11/11，零失败、零跳过，含 2 项关系数据库用例；结果见[复跑报告](../output/refactor-v2/validation-20261120/android-api24/connected-android-test-summary-resume.json)，不替代正式签名 APK 和实际营业机型。本机 Chromium 与真实 PostgreSQL 隔离 schema 已完成后台登录、合成会员搜索/档案及 2 元充值 UI/API 冒烟，余额和单笔流水经数据库核对；该工作站冒烟不替代目标资源、目标 HTTPS 浏览器全流程、正式签名设备及安装器的签收。

## 2. 解耦与持久化验收

架构扫描已覆盖 151 个运行模块的导入图和旧路径、Docker API 发包依赖和外部数据库配置。本机 Caddy 和实际只读挂载已跑通合成导入、归档、恢复和异步表格下载；目标仍须检查实际镜像、SQL 授权和容器文件系统。PG/SQLite 流式归档、各自的有界备份与手机快照是不同合同；按各自格式验证损坏输入、取消、回滚及适用的原号重试。

| 编号 | 检查 | 必须满足 |
| --- | --- | --- |
| ARC-01 | 模块导入图 | 领域层无 Vue/DOM/localStorage/HTTP/pg/原生桥依赖，服务端不导入客户端存储引擎，无循环依赖 |
| ARC-02 | 资金入口审计 | 收银、语音、导入、冲正、同步和恢复均调用同一应用服务，无控制器/组件直接改余额 |
| ARC-03 | 旧代码扫描与运行跟踪 | 无 accounts.data 财务读写、旧 replayOperation、旧全店摘要、旧 localStorage 账本或 v1 双轨路径 |
| ARC-04 | 表与外键 | 会员、资金、期初、流水、项目/支付、收据及配置是独立关系记录；租户复合键和外键有效 |
| ARC-05 | 禁止伪关系化 | 不将整份会员/流水/配置 JSON 存入 JSONB、TEXT 或 BLOB；不以 EAV 文档树替代明确业务表 |
| ARC-06 | API 无本地业务落盘 | 目标只读容器内导入、查询、记账、同步、备份恢复和表格导出正常，无本地业务文件和数据库卷 |
| ARC-07 | 数据库部署位置 | API 连接独立 PostgreSQL，API 主机无业务数据库卷；数据库自己的持久化与备份符合部署定义 |
| ARC-08 | SQLite 持久化 | 使用真实 SQLite；每个连接正确启用/验证外键，记录并核验 journal_mode/synchronous 持久化配置；事务提交失败可观察，重启后已确认交易可读取 |
| ARC-09 | 交易不可变性 | 普通运行账号不能删除历史资金数据，原单金额和归属不能通过任意更新接口篡改 |
| ARC-10 | 数据契约 | 金额单位、整数边界、时间/时区、排序、空值和版本字段有唯一含义，PG/SQLite/网页/Android 一致 |

架构扫描不能只搜索类名：还应检查写入调用图、实际 SQL 和文件系统访问记录，防止旧实现改名保留。

## 5. 逻辑、属性与随机测试

建立独立于正式实现的精确整数参考模型，不能用同一段生产函数计算“期望值”。每步比较账户、期初、流水、冲正关系、版本、收据和审计。

核心不变量：

1. 当前余额 = 期初余额 + 全部新账务净变化，单位分；不通过浮点数运算存储金额。
2. 每笔新流水 after − before = delta；同账户写入顺序连续，时间相同或回拨不改变资金顺序。
3. 成功命令只有一份结果与业务效果，拒绝命令无资金副作用；相同 ID 不同内容必须拒绝。
4. 充值到账 = 实收 + 赠送；冲正关联同会员原单且只能生效一次，历史原单不被抹掉。
5. 正余额和欠款分开核对，修改姓名/电话/标签不改变资金；报表筛选不影响资金事实。
6. 余额、流水、outbox/收据、核心审计在同一事务中一致；不能出现已显示成功但重启丢失。
7. 规则或权限变化在交易提交前重新检查；界面隐藏按钮不代替服务端验证。
8. 分页与增量同步不漏、不重复生效，不将 sequence 的分配顺序误当提交顺序。

固定预算：快速 CI 每轮 100 个固定种子 × 100 步；扩展回归每个存储引擎 1,000 个种子 × 200 步，覆盖充值、消费、冲正、归档、规则改变、失败、重试和时钟变化。失败保留种子与最短复现序列，修复后加入固定回归；本轮实际完成量以同摘要报告为准。

扩展回归入口为 `node tools/relational-randomized.mjs --engine sqlite` 或 `--engine postgres --workers 4`。默认种子 1–1000、每种 200 步；用 `--start <seed> --seeds 1 --steps <step>` 重放失败前缀。PG 仅允许显式标记的本机专用测试库，每个工作者拥有自己的 schema；SQLite 每个种子使用新文件。报告包含逐步的操作类别计数和失败前缀，成功须完成全部种子且源码摘要不变。PG 的测试触发器与 SQLite 测试时钟只控制合成流水时间，授权与连接超时仍用真实时钟。

金额用例覆盖最小分、零、负期初、欠款边界、最大业务允许值、累计/数据库溢出、超精度输入、科学计数输入以及 API/JavaScript/Java/SQLite 类型转换；非法输入不能静默取整或变 0。

## 6. 真实并发与幂等

| 场景 | 计划负载 | 断言 |
| --- | --- | --- |
| 同命令并发重复 | 同 ID 100 请求 | 一份资金效果；结果一致或明确处理中，不重复记账 |
| 同 ID 不同内容 | 50 并发变体 | 冲突拒绝，原交易不变 |
| 同会员同版本 | 50 个不同扣款命令 | 按定义仅一个版本更新成功，其余明确冲突；不能超扣 |
| 不同会员 | 10/50/100 并发 | 合法命令均可完成，不因整店旧版本互斥产生业务冲突 |
| 跨店同 ID | 至少 20 个合成店铺 | 租户隔离，没有串单、跨店权限或唯一键误冲突 |
| 重复撤销 | 50 并发 | 同一原单只有一笔冲正生效 |
| 提交成功但响应丢失 | 100 次注入 | 原号重试/查询找回结果，金额不再次变化 |
| 批量任务重入 | 10 并发执行同任务 | 批次与行操作去重正确，进度可恢复 |
| 增量顺序竞争 | 先取序号后延迟提交、分页途中提交 | 游标不跳过晚提交的有效交易，边界重取不重复生效 |
| 权限/规则并发变更 | 禁用、到期、改规则与交易竞争 | 事务边界明确，不在已失效权限下继续提交 |
| 恢复换代与旧请求竞争 | 排他恢复锁、同步预检后恢复、旧设备重新联网 | 已进入提交的请求与恢复有确定先后；旧代际资金/任务/期初和游标拒绝，不改号、不换绑、不丢待办 |

不同会员吞吐还要与热点会员冲突分别报告。预期 409、限流和失败均单独统计，不能通过大量拒绝请求制造“低延迟”结果。

## 7. 性能与容量验收

以下仍是目标环境验收预算。本机增长样本见实施台账；回环吞吐与桌面 SQLite 不签收独立目标环境或真机。调整预算须在测试前记录理由和批准人。

### 数据集

| 数据集 | 规模 | 目的 |
| --- | --- | --- |
| D0 | 实际 91 人的受控导入副本，期初 + 少量新交易 | 导入与正常单店体验，验收后按规则处理个人数据 |
| D1 | 合成单店 1,000 会员 + 100,000 新流水 | 常规增长、分页、索引和报告 |
| D2 | 合成单店 10,000 会员 + 1,000,000 新流水 | 长期增长、全表扫描和内存问题；独立长任务执行 |
| D3 | 合成 20 店 × 500 会员，各有新流水 | 租户隔离、跨店竞争和全局热点检查 |

CI 使用小型确定性数据；D2 与长期负载在独立压力环境执行。SQLite 同时测 D0/D1，D2 作为增长极限探索，不宣称所有低配手机必须容纳相同规模。

### 环境与负载

- 参考服务环境：API 2 vCPU / 2 GiB，PostgreSQL 2 vCPU / 4 GiB、SSD、独立数据库服务；压测机独立。记录限额、网络 RTT、数据库参数、表大小、索引和日志配置。默认 Compose 的 API 资源限额更小；若生产保持默认限额，另按实际限额复测，不引用参考环境数据代签。
- 预热 5 分钟，稳定负载 20 请求/秒持续 30 分钟，70% 查询、20% 财务写入、5% 同步、5% 管理/审计。查询包含搜索、分页和常用报表；写入使用可验证账户版本。
- 另做 10/50/100 并发阶梯、热点会员、登录失败/日志查询干扰；容量上限探索逐步加压，不以目标请求数代替实际接受吞吐。
- 2 倍、5 倍突发各 5 分钟；验证限流/退避、队列和连接池有界，解除压力后恢复。另做至少 4 小时稳定性运行。
- D2/D3 另测增长归档和异步流水表格。样本须含成交明细、原号回执、同步游标和核心审计。安排至少一轮表格排队、生成与收银稳态同跑，记录 CPU/RSS、数据库池等待、超时与恢复情况，核对 XLSX 快照范围及金额，再执行归档读回、恢复和对账。在同一个空目标库先预览回滚，再正式恢复；记录两次时长及查询计划，覆盖空库统计仍旧时的情况。保留生产超时设置，逐户核对金额和版本，并校验总数没变时也能拒绝缺单、错型和重复审计。
- SQLite 在记录型号、Android 版本和剩余空间的目标真机上执行本地查询/记账、后台恢复与长时间运行；不得仅用桌面 SQL 或模拟桥推算手机结果。

目标负载由独立施压端通过目标 HTTPS 入口发起，按 [REF-03 独立施压步骤](refactor-target-acceptance.md#ref-03-独立施压步骤) 配置合成门店、可见来源与真实认证。`refactor:capacity:postgres` 在同一进程启动回环 API，只供本机调试。目标报告按阶段记录计划、实际发出、成功、预期冲突、限流、繁忙、超时、施压端漏发和非预期失败。突发允许受控拒绝；比较降压后 60 秒内能否恢复到稳态，不能把限流数算进成功吞吐。只在可丢弃数据集注入重启、断连和磁盘故障。

### 暂定通过条件

| 项目 | 门槛 |
| --- | --- |
| 正确性 | 已确认资金错误、丢单、重复记账、跨店泄露均为 0；任何一次出现即失败 |
| API 稳态 | 上述参考环境和 D1 下，20 请求/秒的实际完成量可持续；查询 P95 ≤ 200 ms、财务写入 P95 ≤ 300 ms，P99 ≤ 1 秒 |
| 错误与拒绝 | 稳态无非预期 5xx；预期冲突、限流、排队分别计数，不能掩盖未达到的吞吐 |
| 查询增长 | D2 的会员/流水首屏分页 P95 ≤ 500 ms；普通常用报表 P95 ≤ 2 秒；长范围导出单独异步任务且有上限 |
| 资源 | 无无界队列、连接泄漏、持续内存爬升；记录峰值与稳态曲线，过载有明确拒绝并在 60 秒内恢复到健康服务 |
| SQL 证据 | 高频点查/分页无随整店规模线性传输；给出 EXPLAIN ANALYZE、锁等待和连接池等待，证明资金写入不扫描整店 |
| 手机 | D1 下本地分页和单笔记账 P95 ≤ 200 ms（包括提交），交互不被长任务阻塞；磁盘/事务失败时不报成功 |

这些是发布前需验证的预算，不是现有系统性能承诺。整体用户延迟另记录公网、设备和渲染因素；同步或外部语音耗时不能混入 API 本地资金提交指标来相互掩盖。

## 8. 安全与滥用测试

- 身份：未登录读写、过期/撤销凭据、平台/商家令牌互换、IDOR、跨店请求、越权字段修改、降权、最后管理员竞争、密码爆破与限流。
- SQL/输入：参数化查询、排序字段白名单、注入、超大/深层请求、错误类型、非法 Unicode、原型污染、搜索与分页上限。
- 文件：备份及表格的类型/尺寸/行数、压缩炸弹、损坏内容、公式注入导出、路径穿越；错误不能覆盖现有资金。
- 授权：签名、起止时间、永久/期限、换设备、篡改功能、未知公钥、离线时钟异常；远程禁用对完全离线设备的真实边界如实记录。
- 凭据：密码摘要、Keystore、临时读写失败、卸载/重装、设备标识变化；私钥/令牌不进入包、前端资源、日志和错误响应。
- Web：XSS、CSP、CORS、点击劫持、会话隔离；若使用 cookie，补齐适用的 CSRF 防护测试。
- 数据库：运行身份无 DDL/任意账务删除权限、租户复合外键、业务更改审计、导入专用权限与期初锁定。恢复统计函数须无参数、固定 schema/search_path，普通身份调用拒绝；恢复身份仅能执行固定函数且无 MAINTAIN，撤销执行权时启动检查失败。
- 资源：并发登录、慢请求、超时外部语音、日志洪泛，检查背压、连接释放和资金服务可用性。
- 发布物：依赖漏洞与静态检查、构建签名、更新包哈希/证书、安装包替换和降级尝试。

发布前不允许存在未处置的可利用严重/高危漏洞；扫描结果要人工判定、修复和复测，不能仅写“已扫描”。不宣称纯离线软件能完全抵御 Root、篡改系统或整机状态回滚。

## 9. 故障、恢复和 Android 真机

1. 在余额、流水、收据、审计和 outbox 的每个事务边界注入异常，验证全有或全无。
2. PostgreSQL 断连/重启、事务超时、死锁和磁盘不足：明确失败或找回原结果，不产生半笔账；重试有界。
3. SQLite 忙、磁盘满、写入中杀进程、Android 后台回收/重启：已确认交易可读取，待办不会丢；提交前中断不显示成功。
4. 离线充值/消费后重启、切网、登录过期/降权再同步、同账户远端变动：保留原命令。原号回执能匹配才确认；404 不删除。同代际游标倒退停止写入；缺口或合法换代可由店主重建，须覆盖下载截断、取消、SQLite 提交故障和下载后再次换代。
5. 卸载前外部备份验证、全新安装、导入、飞行模式使用、再次备份恢复；备份只在缓存目录或无法独立读取时，验收失败。
6. 新版开业后产生新交易，再演练恢复，不能用旧期初覆盖新增账；恢复原子创建新账本代际。旧设备待办、已提交/结果未明命令、资料/配置任务、回执查询及会员/流水/报表/增量游标都须拒绝跨代际使用；不得换号、自动补当前代际、覆盖余额或丢弃原待办。覆盖预检后并发恢复、PG 排他恢复锁与在途业务提交、SQLite 恢复提交失败及再次备份恢复。
7. 真机覆盖最低支持 Android API 24 与当前目标机型、窄屏、字体缩放、键盘、铃铛提醒、文件分享及系统安装器返回。
8. 当前不部署主备/集群时，不把主库自动切换测试伪列为已通过；将来启用前须另验 fencing、复制滞后、RPO/RTO 和负载均衡。
