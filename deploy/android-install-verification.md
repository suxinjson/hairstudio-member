# Android 安装时的开发者身份与签名来源提示

适用于“会员管家”安装时出现的“开发者身份未验证”“未验证应用提醒”“身份未经核实”和“签名来源不明”。这些文字是用户提供的系统安装提示，不在本项目界面中；具体判定规则与处理入口取决于手机品牌、系统版本和安装渠道。

## 家人朋友内部使用

内部使用可先按手机系统允许的方式安装，无需为了使用本项目先走应用市场上架流程。手机没有更新系统，也不能排除应用安装来源、实际签名、厂商联网校验规则或验证状态变化；现有资料不足以确定本次提示的原因。

后续更新优先使用 App 的“设置 → 应用更新”：点击“下载并安装更新”，完成同步和安装包校验后自动打开系统安装器；若需开启“允许来自此来源的应用”，授权后返回即可自动继续。未授权或安装器打开失败时，可点击“继续安装更新”重试，同一页面内无需重新下载。系统安装器仍需要用户确认安装。

应用清单已补充真实的用途说明，但应用描述不会成为平台认证，也不保证安装器展示该说明。尚未取得真实开发者认证信息，因此不填造开发者姓名、企业、认证编号或市场来源。

### 由你用电脑协助首次安装

可在家人朋友本人同意并解锁手机后，使用 Android 官方提供的 USB 调试安装通道。它通常可以省去在文件管理器或微信中打开 APK 的步骤，但部分厂商仍要求额外的“通过 USB 安装”授权或在手机上确认，不能保证绕过上述身份提醒。

1. 从 [Android 官方页面](https://developer.android.com/tools/releases/platform-tools)取得 Platform Tools，将受信任发布包放在电脑上。
2. 在手机的“开发者选项”开启“USB 调试”，连接电脑，在手机上确认允许这台电脑调试。具体菜单名称随品牌不同。
3. 在 Platform Tools 目录打开 PowerShell，执行以下命令，将安装包路径替换为实际文件路径：

```powershell
.\adb.exe devices
.\adb.exe install -r 'D:\安装包目录\member-manager-v1.0.69.apk'
```

第一条命令应显示目标手机状态为 `device`。若显示 `unauthorized`，先在手机上完成授权。连接多台设备时，用 `adb.exe -s 实际设备序列号 install -r ...` 明确目标。`-r` 表示覆盖升级并保留数据；需要同一包名、同一签名且版本允许升级，不会修复签名不匹配。若报签名冲突，不要先卸载，应先核对原签名和导出账本。

确认安装成功后关闭 USB 调试，按需撤销调试授权。无需关闭全局安全校验，也不使用伪装应用市场安装来源的参数。本次未连接真实手机，USB 安装是否被该机型允许仍需现场验证。

## 当前项目已经具备的签名保护

- 包名为 `com.hairstudio.memberapp`，来源是 `capacitor.config.json`。
- `android/app/build.gradle` 要求 release 构建提供固定 keystore、别名、密码和版本号。
- `.github/workflows/build-apk.yml` 使用 `apksigner verify --verbose --print-certs` 验证 APK，并比对 `RELEASE_CERT_SHA256`；不匹配时停止发布。
- 应用内更新在安装前校验下载文件及与当前安装版本相同的签名，参见[部署说明](README.md#发布-apk-更新)。

这些措施用于检查安装包完整性和签名连续性，不能证明开发者已在手机厂商或分发平台完成实名认证，也不能保证系统安装器不显示来源提醒。此处只说明仓库配置，不能据此认定用户手里的 1.0.69 安装包已通过实际核验。

## 对应处理

| 安装提示 | 应核对与处理的事项 |
| --- | --- |
| 开发者身份未验证、身份未经核实 | 先确认提示所属的手机厂商或分发平台，使用真实责任主体完成该平台要求的开发者身份认证，再按平台要求关联应用。具体是否支持个人开发者以平台规则为准。 |
| 未验证应用提醒 | 账号认证完成后，还需核对应用是否完成该平台要求的应用审核或身份验证。只有账号认证不一定足够。 |
| 签名来源不明、应用签名未经平台校验 | 先核验实际 APK 签名；签名有效且与历史版本一致时，继续按对应平台要求关联包名和签名证书、提交 APK 或申请来源认证。是否需要上架及是否接受站外分发，以平台提供的流程为准。 |

在证书中手填姓名或公司、换一份自签名证书、升级签名算法，均不能代替平台身份认证。HTTPS 证书与 APK 签名也属于不同用途。不要为消除提示更换现有签名，否则可能无法覆盖升级并影响本机数据。

## 先核验用户实际收到的 APK

在安装 Android SDK Build Tools 的可信电脑上，对实际分发的 APK 执行以下命令（替换工具和文件路径）：

```powershell
& 'C:\Android\Sdk\build-tools\35.0.0\apksigner.bat' verify --verbose --print-certs '.\member-manager-v1.0.69.apk'
Get-FileHash -LiteralPath '.\member-manager-v1.0.69.apk' -Algorithm SHA256
```

检查命令成功退出，核对输出的签名证书 SHA-256 与当前发布配置 `RELEASE_CERT_SHA256` 一致，再核对文件 SHA-256、大小与同次构建的 `update-manifest.json` 一致。证书指纹和 APK 文件哈希是两个不同的值，不能互相比较。指纹比对可忽略大小写、冒号和空白。

如果签名验证失败，或与受信任发布记录不符，停止分发该文件，从原固定签名的 CI 产物重新取包。若丢失原签名，应先查找安全备份，不能通过生成新密钥恢复覆盖升级能力。签名配置见 [GitHub APK 指南](github-apk.md)。

## 平台办理与验收

1. 记录手机品牌、系统版本、安装入口及完整提示，确定需要在哪个平台办理；不能仅凭上述通用文案认定为某一家厂商。
2. 在对应官方开发者平台用真实个人或企业主体完成认证，按照该平台要求准备资料；如要求应用备案、隐私政策或其他材料，再按实际规则办理。
3. 将现有包名 `com.hairstudio.memberapp`、原签名证书指纹和待分发版本关联到该主体，提交平台要求的审核或来源验证。只上传平台要求的 APK、公开证书或指纹，不向认证页面上传 keystore 私钥及密码。
4. 审核通过后，按平台支持的渠道取得并分发安装包。若平台会重新签名，须先确认能否与已安装版本兼容，不能直接拿不同签名的包替换现有更新包。
5. 在原先出现提示的同品牌、同系统及同一安装入口测试首次安装；再测试覆盖升级和账本保留。站外下载与市场安装可能适用不同规则，某一渠道通过不代表所有渠道都不再提醒。

验收应以目标手机上的实际安装结果为准。项目构建或签名测试通过，不代表厂商身份认证已经完成。
