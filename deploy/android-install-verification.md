# Android 签名、更新与真机验收

仅在签收前的隔离环境和专用测试机执行。至少覆盖一台 Android API 24 真机和每种实际营业机型。使用合成 91 人、专用账号和隔离 API；首次云端登录手工填写该环境地址，核对服务器与门店后再确认。需要覆盖安装和卸载时使用同包名的专用测试机，营业机保持原状。

## 固定并核对候选

1. 记录源码摘要、目标环境、包名、版本号和哈希。按 [固定发布签名](github-apk.md) 使用原 keystore；私钥和密码从受控构建环境注入，不写入命令、报告或仓库。候选版本号须高于测试机上用于覆盖升级的基线。指定正确的离线授权公钥配置；签 APK 的证书与签离线许可的公钥是两套材料。
2. 在受控构建机执行：

   ~~~text
   npm ci
   npm run build
   cd android
   bash ./gradlew :app:validateReleaseSigning :app:assembleRelease --no-daemon
   ~~~

   Windows 使用 `gradlew.bat`。构建前注入 `RELEASE_STORE_FILE`、`RELEASE_STORE_PASSWORD`、`RELEASE_KEY_ALIAS`、`RELEASE_KEY_PASSWORD`、`VERSION_CODE`、`VERSION_NAME` 和适用的 `VITE_LICENSE_PUBLIC_KEYS`；Android Gradle 任务不会上传 APK。生产发布开关须保持关闭。
3. 对正式签名 APK 运行 `apksigner verify --verbose --print-certs <候选APK>`。将通过的 SHA-256 证书指纹与已有发布证书、更新清单匹配；另用 `Get-FileHash -Algorithm SHA256` 或 `sha256sum` 校验 APK 文件，核对包名为 `com.hairstudio.memberapp`。包签名正确只表明它由对应密钥签署；系统若提示开发者身份/安装来源未验证，记录系统提示和发行渠道，在设备平台确认发行身份，不覆盖原签名，也不绕过系统策略。
4. `adb devices -l` 只用于确认所选测试机已连接。每台分别记录机型、Android/API、WebView 版本、可用空间、构建包 SHA-256 和签名指纹。调试仪表测试可另行运行 `:app:connectedDebugAndroidTest`，保存结果；调试包安装、编译和模拟器结果不能代替下表的正式签名真机验收。

## 按机型逐项记录

| 用例 | 执行与通过条件 |
| --- | --- |
| AND-01 新装、登录与许可 | 全新安装后无历史业务；未登录或许可无效不能记账。分别验证云端账号和独立离线激活；重启后身份、门店和权限正确，云端首轮同步完成前不能离线写。离线测试用与候选公钥匹配的合成签发码。 |
| AND-02 期初与离线 | 云端加载合成期初，独立离线模式另外导入合成期初；逐人核对 91 条身份、余额和正/负/零人数，确认期初不计入营业报表。飞行模式重开并重复核对。独立离线与云端用各自的测试安装或设备。 |
| AND-03 持久化与原待办 | 断网充值、消费；分别在提交前后终止测试应用进程，后台回收及重启手机后核对原回执、余额和待办。提交前不得显示成功；提交成功不可丢单。恢复联网、会话过期、降权及远端同会员竞争时，不换号、不丢待办；只有身份和原回执匹配才确认。 |
| AND-04 文档写后读回 | 选择应用之外的位置导出完整 SQLite 归档和需要核对的原单；关闭应用，用系统文件管理器或独立设备重新打开并核对字节数、SHA-256。取消、拒绝权限、目标不可写等失败场景不得标为成功。 |
| AND-05 卸载重装及恢复 | 只对测试机操作。先独立读回两份应用外备份；卸载再装同一候选，重新登录或激活，在正确门店恢复合成账本。核对新代际、全部期初、卸载前新增交易和冲正；再记一笔并重新导出。云端副本重建及旧待办走[原单与恢复处置](../docs/refactor-implementation.md#原单与恢复处置)。 |
| AND-06 系统更新器 | 测试环境提供更高版本的同签名包。启动检查、进入更新页自动下载、哈希/包名/签名检查后打开系统安装器。首次退出安装器而未安装，返回仍可继续且复用已校验缓存；恢复安装后应用版本和账本正确。错误哈希、错误签名、包名不符及降级样本不能进入安装流程。 |
| AND-07 交互、空间与性能 | 在窄屏、字体放大、软键盘、铃铛提示、系统文件分享界面检查可达性。记录 D1 真机分页与已提交记账 P95；在专用设备验证磁盘空间不足、SQLite 忙和长任务不挡收银。 |

每条记录开始/结束时间、操作、预期、实际、通过/失败及证据位置；保留原号、金额和水位的合成对账记录。不要录入真实会员信息、访问令牌或设备私钥。任一目标机型缺失、系统安装器未验证、原单或外部文件读回失败，保持发布阻断。
