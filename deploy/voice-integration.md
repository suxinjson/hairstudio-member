# 语音服务与天猫精灵接入

2026-11-06 升级需要同时更新 API、PC 管理端和移动端。先备份数据库，再运行迁移任务；新增 `voice_dialogs`、`voice_requests` 两张表及受限运行角色授权。Docker 部署的 API 新增 `voice_egress` 出站网络，数据库继续只接入内部私网。

## 合成服务

### App 消费与充值播报

金额播报会去掉无意义的末尾零：`38.00` 读作 `38`，`38.50` 读作 `38.5`，`38.05` 保留，负余额保留负号。只调整送往语音合成的文本，账本、金额输入和回执继续保持原精度。服务端同样处理带“元/块”或货币符号的金额，更新 API 后已安装 App 的常用模板和试听即可生效；App/PC 共享播放器还会处理 `{amount}`、`{balance}`、`{gift}`、`{totalCredit}`，自定义语句不带单位也可正确播报。天猫精灵回复采用相同金额文本处理。

App 在消费、充值确认成功且本机账本已写入后，读取已绑定门店的 `/api/v1/voice/config`，按后台保存的消费/充值模板调用 `/api/v1/voice/synthesize` 并播放返回的 MP3。讯飞凭据保留在 API 服务端，App 只提交播报文本；草稿试听成功后仍需启用播报并保存配置。配置在同一账号和门店内缓存 30 秒。

自动播报需要 App 已登录并绑定门店、设备联网且云端登录有效。离线记账仍可正常使用，恢复网络后的账本同步不会补播或重复播报。充值模板的 `{amount}` 是实际付款额，`{gift}` 是赠送额，`{totalCredit}` 是合计入账额；`{balance}` 为交易后余额，保留欠款的负数。只有确认写入成功的交易触发一次播报，取消、写入失败和重复点击均不多播。

App 入口为“设置 → 语音与天猫精灵”，与 PC 管理端共用配置组件。店主可修改播报总开关、消费/充值各自的开关、服务商、音色、音量和两类语句，并试听未保存的草稿；店员/只读账号只能查看已保存的播报配置，不能修改或查看天猫精灵的账号/密钥/设备设置。App 离线、未登录或未绑定时显示连接提示，不提供可误保存的默认配置。

天猫精灵设置包括启用开关、在用店主/店员记账账号、生成与复制新签名密钥、设备白名单、平台域名校验文件和内容，以及复制服务接口地址。已有供应商/签名密钥只显示是否已配置，不返回原文；新输入或生成的密钥在保存、取消或退出页面后清除。App 保存配置不会自动创建开放平台技能或意图，真实音箱接入仍按下方协议执行。

本次新增 `events.consume`、`events.recharge` 两个 JSON 配置字段，旧配置默认两类均开启；只修改其他字段时保留已有开关，不需要数据库迁移。需要同时更新 API、PC 网页和 APK，旧客户端不识别这两个独立开关。配置加载完成前不能保存，保存后立即停止旧播报并清除缓存；后台锁屏、退出账号或权限变化也会停止播报。

消费/充值回执先正常显示；合成或播放失败会提示“记账已完成，语音播报失败”，不会撤销交易。播报按队列顺序播放，退出登录、更换账号/门店或卸载页面时停止播放并取消尚未完成的客户端音频请求。

Capacitor 的 Android WebView 已默认允许异步合成完成后播放音频，无需额外原生权限；播放音量还受手机媒体音量、静音设置和蓝牙音频输出影响。本修复包含 App 代码，必须重新编译并安装包含这些改动的 APK，单独更新服务器或之前的安装包不能生效。运行 `npm run build` 构建并同步 Android 资产，再按 [GitHub APK 构建说明](github-apk.md)使用现有签名发布更高版本的安装包。App 使用现有语音 API，无需为本次 App 播报修复新增数据库迁移。

### 讯飞在线语音合成

管理网页新增“讯飞在线语音”，默认使用普通话“小燕” `x4_xiaoyan`。可选择小露 `x4_yezi`、许久 `aisjiuxu`、小婧 `aisjinger`、许小宝 `aisbabyxu`；具体发音人需要在所用应用的讯飞控制台开通。

按照[讯飞官方在线语音合成文档](https://www.xfyun.cn/doc/tts/online_tts/API.html)，接入采用 `wss://tts-api.xfyun.cn/v2/tts` 和鉴权方式一：将控制台“鉴权信息”中的 APIPassword（`ak-…`）放入 WebSocket 握手 `x-api-key` 请求头。APPID 放在请求的 `common.app_id`。另一组 APPID/APIKey/APISecret 用于鉴权方式二的 HMAC 签名，本接入使用 APIPassword。

更新代码后，在服务器 `.env` 配置 `XFYUN_APP_ID` 和 `XFYUN_API_PASSWORD`，重建 API 与 Web 容器。也可由店主在管理网页填写 APPID 和 APIPassword 并保存到门店配置。网页只返回密钥是否存在，不返回密码。填写的门店密钥优先于服务器环境密钥；清空门店密钥不会删除服务器环境密钥，停用服务器默认密钥需要修改 `.env` 并重新创建 API 容器。

店主选择“讯飞在线语音”后可以先试听，成功后启用播报并保存。合成使用 UTF-8 文本、`aue: lame`、`sfl: 1`，将分段 base64 MP3 拼接后返回给网页播放。合成期限为 60 秒，音频上限为 8 MiB；连接仅允许已批准的 WSS 来源，DNS 固定到验证通过的公网地址，保持证书校验并拒绝重定向。超时、上游异常或提前关闭都会终止连接。此次接入不需要新增数据库迁移。

新依赖 `ws` 位于服务器工作区的生产依赖中，部署时需要同步更新 `server/package.json` 和根目录 `package-lock.json`。不要将真实凭据或本地私密 `.env.*` 文件打包进源码更新包。

### Fish Audio 与 HeyGen

前端不再提供内置 API Key，任何角色的配置响应都不返回密钥。历史公开的两枚密钥已由服务器按 SHA-256 指纹拒绝使用；部署负责人仍须到对应供应商后台撤销旧密钥、检查用量并生成新密钥，再由店主在语音设置页保存。删除源代码不能撤销供应商的凭据，旧 Git 历史或缓存中的凭据应视为已泄漏。

默认允许 `https://api.fish.audio`、`https://api.heygen.com`、`https://resource2.heygen.ai`、`https://files.heygen.ai`（HeyGen 官方 TTS 文档使用的音频来源）。自定义接口或供应商新增音频域名必须由部署管理员设置 `VOICE_ALLOWED_ORIGINS`，填写逗号分隔的完整 HTTPS 来源，例如 `https://voice.example.com`。不填写路径、查询参数、IP 地址或通配符。API 和 HeyGen 音频下载共用此规则，解析到内网/保留地址、混合内外网 DNS 或重定向均被拒绝，实际连接优先选择已验证的 IPv4 地址（只有 IPv6 时使用 IPv6），并继续验证原域名证书。

合成不持有数据库事务；每个 API 进程最多 4 个并行请求，满载返回 429。音频上限 8 MiB，HeyGen JSON 上限 64 KiB，上游错误正文上限 8 KiB。Fish Audio 合成期限为 60 秒；HeyGen 合成期限为 90 秒，返回地址后的音频下载使用独立的 30 秒期限；管理网页等待期限为 130 秒，覆盖两个阶段和代理开销。超时提示区分合成和下载；401/403 提示密钥问题、402 提示额度、429 提示限流或免费模型繁忙。只有店主的 `test: true` 可以试听未启用的草稿配置。

切换服务商时重置接口、模型、音色和输入中的密钥。服务端也不会将已保存的另一家密钥沿用到新服务商；首次切换需要输入当前服务商的 API Key。此次试听修复需同时更新 API 与 PC 管理网页，无额外数据库迁移。

HeyGen [官方 TTS 文档](https://developers.heygen.com/docs/voices/heygen-voice-speech)说明 Turbo Free 的响应时间和服务可用性不保证。调整期限仍无法解决服务器无法访问外网的问题；若继续超时，在 API 容器内分别检查两个 API 来源和 HeyGen 音频来源的 DNS、HTTPS 连通性，并确认容器已接入 `voice_egress` 网络。不要通过关闭证书校验处理连接问题。

可运行 `docker compose exec -T api node server/check-voice-network.js` 检查生产容器出站；IP HTTPS 部署需加 `-f compose.yaml -f deploy/compose.ip.yaml`。本机运行 `npm run server:check-voice`。检查不携带密钥或播报文本，API 返回 401 是未登录的预期结果，只证明 DNS/TLS/HTTP 可达，不能证明密钥有效或合成成功。

## 天猫精灵签名网关

### 真机欢迎成功，但业务句子跳出技能

欢迎回复已缩短为“梦飞空间欢迎您，请说”，仍用 ASK_INF 开麦等待下一句；更新后端服务后生效。补充语料文件 `天猫精灵导入示例/意图例句/002_QueryMemberIntent_补充.csv`、`004_ConsumeIntent_补充.csv` 分别增加“查询苏新用户”“苏新消费100元”等实际句式，导入各自意图并构建模型，会员实体仍须包含实际姓名。不要把 memberQuery 直接改为 sys.select：该实体需要后端先返回 SELECT 和动态候选列表，当前项目没有实现这套流程。

听到欢迎语只证明欢迎请求到达后端，不能证明业务意图识别、音箱绑定和记账确认已经通过。系统回复“给妈妈充话费”“幺的笔顺”等，说明该轮话语被其他技能接走，会员业务后端没有收到该轮指令。

先在平台“语音交互模型 → 实体”核对 `memberQuery` 关联的会员实体，加入实际会员姓名（如苏新）、实际手机尾号或完整手机号。会员库和语料 CSV 不会自动把这些值同步到平台实体；张三、李四只是训练示例。金额关联 `sys.price`，使用“一百元”“200元”等带货币单位的表达。消费的 `service` 关联门店项目实体并设为非必选；会员标识和金额按明确报金额的操作设为必选，不填虚构默认值。

在相应意图中增加并标注实际用语，例如 `苏新消费一百元`（memberQuery=苏新、amount=一百元）、`苏新充值两百元`、`查询苏新余额`；姓名写法必须与真实会员一致。对手机尾号也添加完整表达，例如 `查询尾号0840余额`，0840 必须替换为实际尾号。保存并构建模型后，网页测试先核对意图名称和槽值；网页测试不执行真实记账。

若希望分轮补参数，在参数的“精灵追问”中同时填写追问语句和“用户可能回复”：会员可配置 `@{memberQuery}`、`尾号@{memberQuery}`，金额可配置 `@{amount}`、`消费@{amount}`、`充值@{amount}`。这些回复只用于已经开始的参数追问，不把欢迎后的任意数字自动解释为业务操作。后端追问返回 `ASK_INF` 和 `askedInfos`，其中 `intentId` 来自本次请求，不固定填写测试编号。

真机测试先开启该账号/音箱的真机测试权限，并在本系统保存真实设备绑定。对音箱说“天猫精灵，打开顾客”（若技能呼叫名仍为梦飞管家则使用它），欢迎后等自动开麦，再说完整的“查询苏新余额”或“苏新消费一百元”。消费、充值须等播报会员、金额及余额后回答“是的”；仅在收到记账成功回复后核对流水。成功后的业务响应结束技能会话，下一笔操作需要再次唤起。只有在精灵明确追问会员标识时，才单独报数字；欢迎后报“幺七三零八四零”没有业务动作，当前四个意图不支持这种入口。

后端能把会员标识中的“幺、一、零”等逐位数字转换为电话号码，但只有该轮请求实际进入技能时才生效；它不能改变平台的识别和路由。姓名谐音也不能任意映射为会员，应优先用实际手机尾号核对。

### 自建 Web Service 的确认协议

按[官方响应协议](https://www.aligenie.com/doc/20255408/ehac4c)，消费、充值预览返回 `returnValue.resultType: "CONFIRM"`，使用平台内置肯定/否定模型，不引用意图中不存在的 confirm/deny 参数。平台下一轮携带原意图、原槽和 `confirmStatus: "CONFIRMED"` / `"DENIED"`，不会回传自定义 `confirmationRequestId`；`skillSession.attributes` 当前也不通过 webhook 传递。

只有经过平台 Header 适配认证的 1.0 请求，才使用标准字段绑定确认：同一门店、账号、设备、平台用户和技能会话内，核对 domainId/skillId/intentId、原槽值、参数创建时间 `createTimeStamp`，以及每个槽的 `liveTime` 恰好增加一轮。各参数创建时间和轮次组合只允许生成一次预览，取消/完成后重复组合不能创建新操作。缺少这些字段、确认内容发生变化或开启新技能会话时不执行记账。参数字段含义见[官方请求协议](https://www.aligenie.com/doc/20255408/mxi8t9)。此适配标记由服务器传递，不能通过请求 JSON 或 Header 自行声明。

内部 HMAC 网关保留显式 `confirmationRequestId` 协议。预览只保存待确认操作，不扣款；确认时继续核验账本条件，原有事务、权限、设备白名单和重试去重规则仍生效。这次协议修复只需更新 API 服务，无新增迁移，不会自动清空数据；代码测试已覆盖标准平台请求，但最终仍需在用户的真实音箱和已构建模型上验证整条链路。

### 获取音箱标识并绑定

设备白名单中的 `*` 是普通字符串，不表示放行全部音箱。绑定使用真实技能请求中的 `deviceOpenId`；每次变化的 `requestId` 用于请求去重，不能作为设备白名单。

先在开放平台开启[真机测试](https://www.aligenie.com/doc/20255408/gf4xxh)，使用音箱调用当前技能。已经通过当前签名密钥验证、并携带完整请求/会话/用户/设备标识的未绑定音箱会被列为候选；只保留设备标识、最近请求号、意图和时间，不保存录音、原话、会员或金额。候选在每个门店最多保留 20 台、约 1 天；更换签名密钥后旧候选失效。

店主进入“语音设置 → 天猫精灵语音记账 → 待绑定音箱”，点击“刷新待绑定音箱”，选择“加入允许设备”，再点击“保存播报配置”完成绑定。加入时会移除无效的 `*`，保留其他已有设备。待绑定请求仍不能读取账本或记账，店员和只读账号不能查看候选列表。

本次增加 `voice_device_candidates` 表及受限运行角色授权，需要运行迁移并更新 API 与管理网页；App 使用同一配置组件，需安装包含本次更改的 APK 才会显示候选入口。正常启动或部署不会自动绑定音箱。

平台使用自建 Web Service 时，当前接口也支持在请求 Header 中配置 `x-aligenie-token`，值必须与门店已保存的新签名密钥一致；入口按该凭据找到已启用门店并生成内部签名。不要将密钥写入公开前端。此 Header 适配不补造用户、设备、请求或会话标识，也不取消业务请求的设备白名单校验。

平台测试未提供业务标识或使用未绑定虚拟设备时，欢迎请求在验证凭据及门店已启用后仅返回固定引导语，不读取账本、不保存待办或回执。完整且已绑定的欢迎请求沿用原有会话重置与回执流程。确认、取消不会被当成欢迎请求；查询、充值、扣款仍须提供下述稳定标识并通过真实设备白名单。`*` 是普通字符串，当前不表示通配设备。

平台[官方请求协议](https://www.aligenie.com/doc/20255408/mxi8t9)明确说明，网页在线测试的 `requestData` 和 `device` 不携带用户、设备标识；创建意图、开启权限或填写 `*` 不会补齐这些字段。网页测试可验证欢迎语和意图/参数识别，真实账本操作须使用已绑定音箱真机测试。经 `x-aligenie-token` 验证的请求缺少业务标识或设备未绑定时，接口返回 HTTP 200 的技能响应，`returnCode: "0"`、`executeCode: "SUCCESS"`，正常播报具体原因；`msgInfo` 携带业务拒绝码及缺少的字段或待绑定设备标识。这里的 SUCCESS 表示解释性对话响应成功，不代表查询或记账成功，不读取或修改账本。按[官方响应协议](https://www.aligenie.com/doc/20255408/ehac4c)，此类限制应通过正常回复解释；使用 PARAMS_ERROR 等错误执行码会使平台显示“服务开小差”等兜底回复并掩盖原提示。无效凭据以及内部签名 API 的 HTTP 400/401 行为仍保留。

旧的缺省门店选择及无凭据请求已停用，历史配置默认关闭。店主在 PC 的语音设置页选择在用店主/收银员作为记账账号，填写设备白名单，生成并保存新的随机签名密钥。不要复用历史 webhook token。签名密钥只存放于 API、平台服务配置和受控网关；不得嵌入网页或设备端，也不得部署无鉴权的公网转签名代理。

网关先按平台官方接入规则验证请求身份，再从已验证的平台请求中取得用户、设备、请求和会话标识。若当前平台无法提供可验证身份，应保持语音记账关闭。不要直接相信未经鉴权的来访者提交的这些字段。

网关调用 `POST /api/v1/voice/aligenie`，使用 HTTPS，并提供：

| 字段 | 要求 |
| --- | --- |
| `x-store-id` | 明确绑定的门店 UUID |
| `x-aligenie-timestamp` | 当前 Unix 毫秒时间，13 位；允许前后 5 分钟 |
| `x-aligenie-signature` | 下述 HMAC-SHA256，64 位小写十六进制 |
| 请求体 `requestId` / `request.requestId` | 每次平台请求的稳定唯一标识；重试保留原值与原正文 |
| `sessionId` / `session.sessionId` | 稳定会话标识 |
| `context.System.device.deviceOpenId` | 已验证且在白名单中的设备 |
| `context.System.user.userOpenId` | 已验证的平台用户 |
| `confirmationRequestId` | 确认时回传预览响应的同名字段，绑定所确认的原请求 |

签名原文为 `timestamp + "\n" + storeId + "\n" + canonicalJSON(body)`，不包含末尾换行。`canonicalJSON` 按键排序对象、保持数组顺序，使用仓库 `src/sync-protocol.js` 导出的实现。Node.js 网关可调用 `server/aligenie.js` 导出的 `signAliGenieRequest(secret, timestamp, storeId, body)`；其他语言必须采用一致序列化方式。

```js
const timestamp = String(Date.now());
const headers = {
  'Content-Type': 'application/json',
  'x-store-id': storeId,
  'x-aligenie-timestamp': timestamp,
  'x-aligenie-signature': signAliGenieRequest(secret, timestamp, storeId, body)
};
// 使用 HTTPS 发送 JSON.stringify(body)。网络重试保留 body，可更新时间和签名。
```

鉴权失败返回 HTTP 401/403；请求格式无效返回 400；同一请求单号换正文返回 409。查询也要求签名。确认前的待办有效期为 5 分钟，绑定门店、记账账号、设备、平台用户、会话及配置；确认必须引用原预览。取消后的晚到确认不能执行新待办。

预览保存固定业务单号、时间及会员/规则条件。余额、会员资料、归档状态、服务价格或充值规则变化时，确认被拒绝，需重新发起并确认。财务写入、待办消除及响应回执在同一数据库事务提交；失败保留原待办，重启后可继续，成功请求重试返回原响应，不重复入账。响应回执保留一天，每店最多 10,000 条；每店最多 256 个有效待办。过期请求时间戳不能重放。

## PC 版本冲突恢复

已见版本按服务器来源和门店持久保存，重载、退出登录及多窗口均不清除。检测到回退、同版本校验值变化或损坏后禁止财务同步。PC 上传前检查云端版本，并在 `/sync` 中携带 `observedHead`，API 在账本锁内再次检查。

店主解锁后点击“导出版本冲突并核对账本”，确认导出文件已保存并核对本机记录、原待办和云端账本，然后明确选择云端版本作为新基准。服务端核对预期版本并记录审计事件；原待办及导入进度保留，继续核对或取消未入账操作。云端自身校验失败时必须先修复服务器数据，不能通过该流程绕过校验。
