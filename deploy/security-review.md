## 已修复的问题

### 并发登录绕过失败次数限制

原实现先查询失败次数，计算密码后才增加计数；24 个并发错误登录都能进入校验。现在在 PostgreSQL 事务中按固定顺序原子预留账号/IP 额度，再进行 scrypt：每 15 分钟最多 10 次失败或正在校验的请求，超额返回 429。成功只退还同一窗口的失败预留额度，不重置其他失败；额外保留账号 60 次、IP 120 次的总尝试额度。数据库共享额度适用于多进程和多实例，拒绝请求会回滚其所有预留。

密码计算全进程最多同时 4 个，等待队列最多 16 个；满载返回 503。登录重新锁定用户检查停用状态和密码变化，每个用户最多保留 20 个未撤销会话，旧会话被撤销。过期会话和旧登录计数会清理。

### 无权限请求先消耗密码计算或大备份解析

创建账号和初始迁移先从数据库读取有效会话与实际角色，再处理输入。HTTP 层在读取这些接口的大请求体前检查店主权限；只读账号的同步请求也在读取正文前拒绝。服务函数独立执行权限检查，写入事务再次核对，避免检查期间的撤权/降权产生写入。客户端自称角色或门店不会授权。

### 字段、JSON、备份及累计账本缺少容量边界

新增 src/data-limits.js，本机变更、备份解析、同步协议与服务端共用规则：

| 数据 | 上限 |
|---|---|
| 会员姓名、服务名、账号显示名、门店名 | 128 字符 |
| 电话、付款方式 | 64 字符 |
| 会员备注 | 2000 字符 |
| 输入交易备注/撤销原因 | 4096 字符 |
| 系统生成的流水完整备注 | 8192 字符 |
| 业务 ID | 128 字符；同步/设备 ID 保留更严格格式 |
| 会员 / 流水 / 服务 / 充值档位 | 20000 / 50000 / 500 / 200 条 |
| 每个门店账号 / 每个账号有效会话 | 100 / 20 个 |
| 账本 JSON / 备份文件 | 10 MiB / 20 MiB |
| 普通同步批次 / 店主迁移或恢复请求 | 2 MiB / 32 MiB |
| 普通单条同步操作 / 单条业务参数 | 512 KiB / 64 KiB |
| 登录、刷新、账号管理请求 / 连接记录请求 | 16 KiB / 64 KiB |
| JSON 深度 / 节点数量 | 24 / 1000000 |

还校验参数类型、生成 ID 和时间、前置条件，并拒绝 NUL、未配对 Unicode 代理字符、循环对象及危险对象字段。超过容量返回 413，格式错误返回 400。每次变更在落盘前检查最终账本规模；失败时不写账本、审计或去重记录，不删旧流水来腾出额度。历史可选姓名、电话及备注字段仍按原规则补齐；超限旧账本须先导出并由管理员处理容量，不能静默截断。

客户端按条数和实际 UTF-8 字节数分批同步，恢复操作单独发送。较大的合法服务列表前置条件也能继续同步，确认成功才清除相应待办。

### API 使用 PostgreSQL 超级用户

默认部署分成 migrate 管理员任务和 api 运行进程。原管理员 member 与 POSTGRES_PASSWORD 保留，兼容已有数据库卷；新增独立 APP_DATABASE_PASSWORD 和 member_app 角色。迁移负责建表、配置角色与明确授权，API 启动不再建表。

运行角色无超级用户、建库、建角色、复制、RLS 绕过、角色继承或成员资格；不能创建 public schema 对象或临时表，也不拥有数据库对象。API 对更新发布表只读，不能删除账本或更新/删除审计与去重记录。所需业务表采用明确读写授权，审计序列只允许使用。生产启动检查实际角色和超额权限，配置错误时拒绝启动。

创建初始门店、迁移和 APK 发布改用一次性管理员容器。API 容器没有管理员密码，根文件系统和 APK 卷只读，丢弃 Linux capabilities，禁止提升权限。配置了内存、CPU 和进程上限。升级步骤见 [部署维护说明](README.md#已有部署升级)，不要删除数据卷。

### 伪造代理头冒充 HTTPS 和改变限流 IP

生产 API 只接受来自明确配置的可信代理 IP 的请求；没有配置时拒绝请求。默认 Compose 给 Caddy 固定私网地址 172.30.184.10，API 只信任该地址，不信任整个私网。IPv4-mapped IPv6 地址会规范化。

可信代理还必须提供准确的 X-Forwarded-Proto: https 和有效的最后一跳客户端 IP。不可信连接伪造这些头仍被拒绝；在代理前伪造更早的 X-Forwarded-For 地址也不能改变限流标识。Caddy 使用标准 reverse_proxy 转发头处理。公网仅发布 80/443，后端专用端口 48927 和数据库 5432 不对外暴露。

### 真实 PostgreSQL 的服务修改/删除同步失败

真实数据库测试还发现，pg 驱动会将 JavaScript 数组按 PostgreSQL 数组编码，服务修改/删除返回的数组不能直接写入 JSONB 去重结果。现已显式序列化业务结果；这些写入及重试在真实 PostgreSQL 验证。

## 接口权限

| 接口/功能 | 未登录 | 店主 | 店员 | 只读 |
|---|---|---|---|---|
| 健康检查 | 可用（生产须经 HTTPS 代理） | 可用 | 可用 | 可用 |
| 登录、刷新会话 | 校验凭据/刷新令牌 | 同左 | 同左 | 同左 |
| 查看账本、版本头、更新清单和 APK | 401 | 可用 | 可用 | 可用 |
| 建档、修改会员、充值、消费 | 401 | 可用 | 可用 | 403 |
| 注销会员、撤销、服务定价、恢复备份 | 401 | 可用 | 403 | 403 |
| 初始迁移、账号管理、读取审计记录 | 401 | 可用 | 403 | 403 |
| 上传连接记录 | 401 | 仅本账号/设备 | 仅本账号/设备 | 仅本账号/设备 |
| 退出登录 | 401 | 仅本会话 | 仅本会话 | 仅本会话 |

角色与门店均来自有效会话，操作的 actorId/deviceId 须匹配该会话，不能靠请求中的角色或门店越权。停用或降权会撤销旧会话；写入事务重新检查。最后一位在用店主不能被停用或降权。

金额以整数分保存，服务端重算余额和流水，拒绝超额消费、错误前置条件、非法金额、异常冲正与重复活动手机号。一个批次的账本、版本、审计与操作去重记录在同一事务提交；改变同一操作 ID 的内容被拒绝。

## 资源与传输防护

生产 API 每进程限制 IP 每分钟 180 次、登录/刷新每 IP 每分钟 30 次、会话每分钟 120 次、账号写请求每分钟 30 次、创建账号每分钟 10 次、初始迁移/恢复每分钟 3 次。全进程最多处理 32 个请求，账本相关接口最多同时处理 2 个；限流状态最多 10000 个条目，过期后复用，满载返回 503。断开的请求在后台工作结束前仍占用处理额度。普通请求预算是进程内的，多个 API 副本各有一份；登录额度由 PostgreSQL 共享。

HTTP 请求 30 秒超时，头部 15 秒，keep-alive 5 秒；每连接最多 100 个请求，最多 256 个连接。拒绝未获允许的浏览器来源和非 JSON 正文，禁用响应缓存，并返回 nosniff。CORS 不是身份校验，非浏览器仍须令牌和权限检查。

密码是随机盐 scrypt 摘要，数据库保存随机令牌摘要；刷新轮换及上一令牌重放撤销保留。浏览器令牌只在内存，刷新须登录；Android 使用 Keystore AES-GCM 保存刷新凭据并排除系统备份。更新下载须登录且限定路径，App 校验文件、包名、版本和固定签名。

只有 IP 可使用公开信任的 HTTPS 证书，配置见 [124.70.184.136 的 IP HTTPS 部署](ip-https.md)。Let’s Encrypt IP 证书为 160 小时，须自动续期并重新加载 Caddy；不能用 Caddy 本地 CA 证书代替公开信任证书，不能关闭 App 验证。
