# v2 云端部署与运维

本文用于隔离验收和获准后的新库部署。**当前候选不得用于营业切换。** 旧版本停写、真实 91 人期初和回退按 [切换方案](../docs/relational-refactor-assessment.md#8-一次性切换流程)。v2 不在旧库原位升级；迁移检测到旧账表即停止，保留原库和两份独立备份。

## 首次启动

1. 准备独立 PostgreSQL 服务及全新数据库。只允许 API/迁移主机访问，设置合适连接并验证数据库服务器身份；应用 Compose 不运行 PostgreSQL。迁移身份需能创建 schema 对象、配置受限角色和权限。用隔离库先验证，避免共享集群同名角色及密码影响其他数据库。
2. 根据 `.env.example` 配置 `.env`，仅部署用户可读。域名场景设置 `PUBLIC_DOMAIN`、`VITE_CLOUD_SERVER_URL`；只有 IP 时使用 [IP HTTPS](ip-https.md) 的 Compose 覆盖及证书。不同环境分开保管连接串，密码在连接串中编码。
3. 域名模式待证书和数据库就绪后运行 `docker compose up -d --build`。一次性迁移成功才启动 API；不传迁移或签发管理员凭据给 API。若已配置离线授权签发，须叠加 [授权密钥配置](../docs/platform-operations.md#密钥准备)。
4. 检查 `docker compose ps` 和 `docker compose logs --tail=100 migrate api web`。通过 HTTPS 验证 `/api/health` 与 `/api/ready`，分别表示进程存活、数据库连通。还须验证角色、TLS、源限制、备份流、中断及只读文件系统。默认仅代理公开 80/443，不对外开放 48927 或数据库端口。
5. 使用 [平台初始化](../docs/platform-operations.md) 创建首位管理员、空门店/店主及授权。新门店默认未授权。正式期初只到已核对的本店空账本；网页、后台和 APK 一起切换。

| 配置 | 值与用途 |
| --- | --- |
| `MIGRATION_DATABASE_URL` | 外部新库的迁移/运维连接；只进入 `migrate` 作业 |
| `DATABASE_URL` | 同一个库的 `member_app` 连接；API 使用，禁止 DDL/历史账务删除/代际变更 |
| `APP_DATABASE_PASSWORD` | `member_app` 独立 32–256 位随机密码，由迁移设置，与应用连接串匹配 |
| `RECOVERY_DATABASE_PASSWORD`、`RECOVERY_DATABASE_URL` | 可选：同库 `member_recovery` 独立密码与连接串；没有配置恢复连接时，恢复返回 503；不得以管理员连接串代用 |
| `TRUSTED_PROXY_IPS` | Compose 从 `MEMBER_PROXY_IP` 注入固定 Caddy 地址；网段冲突同时调整 `MEMBER_PRIVATE_SUBNET`，核对可信转发头 |
| `RELEASE_CERT_SHA256` | Android 发布签名证书指纹，与 HTTPS 证书无关。只用于已批准发布。 |

迁移会安装固定业务表的统计刷新函数，恢复角色通过它修正大批导入的查询计划。函数无参数、固定 schema 与 search_path，PUBLIC 和普通应用角色无执行权；无需给恢复账号 MAINTAIN、表所有权或管理员权限。升级候选须先完成迁移及角色配置；恢复连接缺少该函数执行权时，启动检查会失败。

访问：`/` 在线收银，`/admin/` 商家后台，`/admin/platform.html` 平台后台。Android 首次在线登录显示实际服务器和门店，首次成功拉取完整水位后才可本机记账。独立离线激活只用本地账本，不向云端上传余额。授权到期或退出会锁定，离线设备不能实时获得远端停用消息；联网后所有上传按当前身份、权限和代际核验。

## 已有部署升级

从 v1 到 v2，按 [一次性切换流程](../docs/relational-refactor-assessment.md#8-一次性切换流程) 在隔离环境演练，再约维护窗口。保留旧数据库主机/卷、APK 和两份应用外独立备份；不要对旧库运行迁移，也不要将旧应用指到新库。新库只按候选文件导入期初，不复用旧账号会话和历史交易。重装前先核对云端已导入的 91 人与外部备份，确认最后旧单和原待办均已处置。

v2 到 v2 的后续升级保持相同数据权威，先备份并验证可恢复性，再部署已验收候选。停止迁移失败时检查目标库、角色、连接和迁移日志，不靠删除库/卷重试。旧设备遇代际或水位异常时参照 [原单与恢复处置](../docs/refactor-implementation.md#原单与恢复处置)。

### 日常仅部署服务器

提交并推送 `main` 后，Actions 的自动运行只验证和编译，不代表服务器已更新。需要真正部署时，发起新的“编译安装包与服务器部署”工作流，分支选 `main`，`operation` 选 `deploy_server`；安装包类型会被忽略。部署需现有 SSH 配置及 `RELATIONAL_RELEASE_APPROVED=true`，详见 [工作流操作](github-apk.md#5-重新构建与下载)。

此模式构建服务器更新包，保留现有手机更新清单和 APK 文件，更新 Web/API 后核验 HTTPS 与数据库就绪，不执行 `server/publish-release.js`，不增加手机新版记录。现有 App 继续调用服务器 API，在线网页刷新后使用新页面，无需安装手机软件。

已将获准的新代码放到服务器部署目录时，也可执行 `bash deploy/deploy-update.sh --server-only`。普通不带参数的旧命令仍可能发布目录中的 APK，日常仅服务器更新应明确使用这个选项。

修改手机 APK 内的页面、离线逻辑或原生功能时，选择 `deploy_server_and_app`，使用原签名发布一次新 APK，用户在手机确认安装。Android 的本地资源不会因 Web/API 部署而替换。

## 备份与恢复

- **业务归档：** 商家后台店主使用“账本备份和恢复”，在支持外部选择与重新读取文件的 HTTPS 浏览器（如 Chrome/Edge）导出流式 NDJSON，成功读回后再从应用外独立打开。独立离线 Android 通过系统文档选择器导出 SQLite 对应格式。云端绑定手机是副本，不能用本地文件覆盖云端；手机有未提交原单时需另外保存并核对。
- **数据库备份：** 由独立 PostgreSQL 的运维备份系统执行，或在能验证数据库身份的运维主机用只读备份身份执行 `pg_dump -Fc`。应用容器没有数据库卷。保留加密的异机副本、账号/授权配置、恢复角色配置、签名与授权密钥；在隔离数据库完整恢复并对账，不能只看备份任务成功。
- **演练业务恢复：** 新目标与原来源隔离，保留原权威库、APK 和未确认原单。用下述命令准备同门店 ID 的空业务账本，另行通过平台配置在线授权。启用恢复专用角色，先预览回滚校验，核对摘要、数量与历史操作人，再用原任务号提交。恢复产生新代际；后续新交易不能被原任务重试覆盖。实际故障保留新交易，再按已经演练的流程执行；不要直接开放回退物理库让设备在原代际写入。
- **新开账与灾备分开：** 旧 JSON/CSV 只经一次性转换用于 91 人期初；v2 归档是完整新版业务关系数据，格式不能互换，不含密码、会话、授权或语音密钥。
- **查账表格：** 会员或财务流水 XLSX 用于查账，不可恢复账本；异步任务状态及成品不进业务归档。

从已独立读回的 v2 云端归档核对原门店 ID，与运维记录交叉确认。在已完成迁移、尚未创建任何门店的独立目标库上，用运维身份执行只读预检：

~~~sh
node server/prepare-recovery-target.js --database '<目标数据库名>' --store-id '<原门店 UUID>' \
  --store-name '<门店名称>' --owner '<恢复操作账号>' --display-name '<恢复操作人显示名>'
~~~

仅给本次进程注入目标库的 `MIGRATION_DATABASE_URL`。预检返回 `ready` 后，核对连接主机、数据库名和门店编号；经运维确认，安全注入 `MEMBER_RECOVERY_OWNER_PASSWORD`，再用原参数追加 `--apply`。此命令拒绝有门店的目标库、旧库、错误数据库名和应用/恢复角色。它只建原 ID 的空门店及新店主，不授予许可，也不导入账务。再按平台流程授予所需功能，通过目标应用用该店主登录并预览归档；未在目标库重建的历史操作人自动保留为不可登录的历史引用。该新账号不能代替原账号核对原手机上的待办。

## 发布 APK 更新

只有 [发布门槛](../docs/refactor-test-plan.md#10-发布清单与完成状态) 签收后，才可按 [GitHub APK 签名](github-apk.md) 人工批准发布。使用同一产物的固定签名 APK 与 `update-manifest.json`，比对源、版本、签名证书及 SHA-256，再发布到相同配置的服务器。服务器用一次性迁移/运维作业运行 `server/publish-release.js`，API 对包及清单只读。不要把 Debug APK 交给旧版覆盖升级。

Android 下载后须核对哈希、包名、版本和签名，再打开系统安装器；退出安装器后重试应复用校验通过的缓存。首次安装、授权、卸载重装、读回及更新流程须在测试机实测，详见 [Android 安装验收](android-install-verification.md)。
