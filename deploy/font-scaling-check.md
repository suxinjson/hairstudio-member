# 简易模式与老人模式排版修复

应用保持现有字号，Android Activity 的 `fontScale` 固定为 `1.0`，WebView 的文字缩放固定为 `100%`。启动、字体配置变化和返回前台时均应用此规则，仅影响本应用；显示密度仍跟随设备配置，通过窄屏布局适配系统显示放大。

网页固定 `16px` 的 rem 基准，同时保留浏览器文字调整为 `100%`。移除了覆盖 Tailwind 间距工具类的全局 margin/padding 重置；文字按钮可随换行增高，充值套餐在窄屏改为两列，充值和扣款抽屉可整体滚动。会员详情改为仅内容区域滚动，底部“额度充值”“剪发扣款”固定在同一行，并留出手势安全区。

头部品牌与“新客户”按钮保持单行。窄屏按可用宽度显示“梦飞会员管家”或“梦飞会员”，图标缩小，日期和状态显示为“11/02 · 离线”等简写；登记按钮字号保持 `16px`，触控高度至少 `44px`。搜索框高度收紧至 `48px`，保留顶部状态栏安全区。极窄屏或短屏允许头部随页面滚动。

主导航为“客户 / 流水 / 设置”。客户页共用最近来店、全部客户、低余额和欠款客户列表，行内直接扣款，档案中查看偏好、历史并充值。“今日小店收银简报”保留在“流水 → 收银简报”。姓名、手机号、尾号与流水关键词在输入变化、失焦和输入法提交后立即模糊搜索，简报视图隐藏搜索框。标准服务不自动打开键盘，改价时点击金额。

## Android 回归验证

使用 Java 21、Android SDK 35 和连接的测试设备，在项目根目录运行 `npm run build` 后执行：

```powershell
cd android
.\gradlew.bat connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=com.hairstudio.memberapp.FontScalingTest
```

新增的 `FontScalingTest` 检查启动与重建后的应用字号、模拟字体配置变化时 WebView 缩放复位、设备密度和语言保留，以及返回前台时文字缩放复位。

真机验收步骤：

1. 开启手机简易模式/老人模式，将系统字体与显示大小调到最大，再启动新版 App。
2. 检查客户页四类筛选、负余额档案、欠款扣款确认框、还款充值、流水和设置页；文字不重叠，不出现横向溢出，底部导航不遮挡操作。欠款确认框应可滚动到知晓勾选框与确认按钮。
3. 使用长会员姓名和较大金额检查会员详情、新建会员、充值套餐、充值确认、扣款键盘和新增服务弹窗；会员详情内容滚动时，两个底部操作按钮不移动且均可点击，其他表单提交按钮可通过滚动到达。
4. 在充值或扣款表单中输入未提交的内容，切到系统设置修改字体大小，再返回 App；字号稳定，未提交内容保留。
5. 退出简易模式后再次打开 App，并检查横屏或短屏下的滚动与按钮显示。

## 本地验证范围

本次统一客户入口与欠款升级已完成 Node 回归测试（191 项，188 项通过，3 项真实 PostgreSQL 并发测试因未配置测试数据库跳过）；前端构建和 Capacitor Android 资源同步成功。新回归覆盖欠款确认、余额变化后重新确认、部分还款、欠款撤销、备份/合并/快照/CSV、云端欠款同步和防重复记账，原有权限、恢复、导出、返回层级及搜索测试继续通过。

本次浏览器检查使用 Android 原生桥模拟，覆盖 240、280、320、360、390、480、760 CSS 像素宽度；客户列表与超额扣款、欠款确认、欠款档案和部分还款均无页面或按钮横向溢出。检查了 320px 窄屏截图，确认红色提醒、欠款金额、知晓勾选框和确认按钮可见，较短屏幕的确认内容可滚动。

重构前的历史验证曾使用 Android 原生桥模拟、长姓名、大额余额和多笔交易，并将默认字体设为 `32px`，检查应用仍保持 `16px` 的根字号；覆盖 240、280、320、360、390、480、760 CSS 像素宽度及不同像素密度，共验证 168 组页面布局。范围包含原收银台、会员库、流水及简报、各类弹窗、设置子页面、离线缓存账号和通过模拟 API 加载的账号列表与使用记录。

浏览器验证不能替代厂商老人模式的真机验证。当前开发机仅检测到 Java 8，未配置 Android SDK，因此未在本机执行 Android 编译和上述设备测试；该原生修复须随重新构建的 APK 安装后生效。
