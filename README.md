# 💳 会员管家（独立安卓原生 App）

适用于各类门店的会员储值、充值与消费记账软件，支持安卓 App、网页收银和管理后台。软件名称统一为 **会员管家**；门店名称、电话、地址、会员备注标题、语音欢迎词与充值通知致谢可在“设置 → 门店设置”中配置，联网后多端共用。已有门店名称与账本继续保留。

现已加入可自部署的私有云：安全登录、店主/店员/只读权限、离线待办与联网同步、服务端原子记账和去重校验、使用记录、检查更新及校验后下载/安装 APK。原有单机模式和 JSON 备份继续可用。部署步骤、权限范围和断网冲突处理见 [云端部署说明](deploy/README.md)。

App 的“设置 → 语音与天猫精灵”支持播报总开关、消费/充值独立开关、音色、音量、语句及试听，店主可配置天猫精灵记账账号、签名密钥和设备白名单。消费与充值成功后按门店已保存配置播报，离线同步不重复播报，音频失败不影响记账。发布需同时更新 API、PC 网页和 APK；配置与接入步骤见 [语音说明](deploy/voice-integration.md)。

接口权限、会话和数据库最小权限说明见 [安全配置](deploy/security-configuration.md)。已有服务器升级需新增独立应用数据库密码并迁移私有网络，步骤见 [升级说明](deploy/README.md#已有部署升级)；只有 IP 时使用 [IP HTTPS 部署](deploy/ip-https.md)。

> 💡 **解决的核心痛点**：
> 1. **彻底摆脱老旧电脑**：独立安卓原生软件，装进手机后电脑彻底拔电源关机，每天开店直接手机秒开秒记。
> 2. **免除应用商城高昂门槛**：免软著、免营业执照、免上架各大应用市场，生成的 `.apk` 安装包微信发到手机 10 秒直接安装。
> 3. **本地账本与外部备份**：账本保存在应用沙盒中；内置文件导出与系统分享，可发送到微信或文件管理器，并在换手机时导入恢复。

## 🌟 门店会员管理

1. **快捷消费扣款**：
   - 新门店不预置行业专用服务，店主自行配置服务项目与价格；消费也支持手动输入金额。已保存的服务项目和价格保持原样。
   - 收银与会员库合并为“客户”入口：最近来店、全部客户、低余额、欠款客户共用一份列表，姓名/手机号/尾号即时查找，行内一键进入扣款，点击客户查看档案与充值。
   - 常用服务自动带入金额，选择标准项目时保持键盘收起，改价时再点击金额打开大按键数字键盘。
   - 支持超出余额扣款和负余额欠款：金额与欠款提示变红，确认框展示原有欠款、本次新增欠款、累计欠款，勾选知晓后才能入账。确认期间余额变化会要求重新核对。
   - 充值及赠送到账额度自动抵扣欠款，部分还款、结清和剩余储值均可查看。欠款未清不能注销；撤销充值如果恢复欠款，需要明确确认。流水、备份、快照、CSV 和云端同步均保留负余额。
   - 客户储值余额与待收欠款分开统计，避免正负余额抵消；最近来店按未撤销消费记录排序，编辑资料或充值不会改变来店时间。
2. **充值赠送与微信通知**：
   - “设置 → 服务与价格 → 充值赠送设置”可开启或关闭赠送，配置 0–100% 的比例（最多两位小数）。默认开启、比例 10%；快捷档位和输入金额都按当前比例自动计算到分，可手动调整赠送金额。关闭后不展示赠送入口，记账也拒绝赠送。
   - 充值表单独立滚动，到账预览与“核对充值信息”按钮固定在底部安全区内。收款渠道单行展示、选填，再点已选渠道即可取消；未选渠道的流水不标记付款方式。
   - 充值成功自动生成专业致谢通知文案（*“尊敬的顾客，本次充值已入账...当前卡内余额...”*），一键复制微信发给顾客。
3. **会员偏好与备注**：
   - 记录服务偏好、客户需求与注意事项；备注标题可按业务设置。
4. **双保险对账与微信备份**：
   - **一键备份发到微信**：打烊后点一下，备份文件直接发到微信“文件传输助手”长期留底。
   - **换新手机一键还原**：新手机安装 App 后，导入备份文件，1 秒全量恢复所有会员、余额和流水。
   - **导出 Excel 表格**：自动生成 `.csv` 对账明细，手机 WPS 随时打开核算。

## 💻 PC 端后台管理系统

针对门店店主、店长与财务电脑大屏设计的独立 PC 管理后台：

- **网页入口**：浏览器访问网站根地址 `/` 打开在线收银页面，访问 `/admin/` 打开独立管理后台。两个页面登录后直接加载服务器账本，不读取浏览器旧的本机账本、离线待办或迁移记录；安卓 App 继续使用本机账本与离线同步。
- **启动开发环境**：`npm run admin:dev`（默认运行在 `http://localhost:5174`）
- **构建生产包**：`npm run admin:build`（输出至 `admin/dist/`）
- **核心功能**：
  1. **批量安全导入**：支持 Excel (`.xlsx`, `.xls`) 和 `.csv` 文件，自动清洗公式注入（Formula Injection 转义），智能表头识别映射，重复手机号可选跳过/累加/覆盖，支持一键导出失败记录修正表。
  2. **会员档案大表**：大表分页高密度展示、快速检索、手机号默认中段脱敏防偷窥、单人充值与档案修改。
  3. **财务流水穿透对账**：所有消费、充值、撤单冲正记录完整溯源，支持一键导出财务对账 Excel 表格。
  4. **服务与定价配置**：自定义服务项目标价维护与充值赠送规则配置。
  5. **员工与权限隔离**：开通店员账号，细分店主、店员、审计员角色。
  6. **安全屏保锁屏**：15 分钟无操作自动锁屏，支持一键快捷锁屏保护客户隐私。

### 手机登录与设备授权

手机登录后自动保持会话，多设备、多页面登录互不挤掉。后台店主在“设备授权”设置手机名称、备注、授权到期日与离线时长，也可禁用设备或禁止离线。首次未登录默认试用 7 天，已登录设备默认每次联网核验后可离线 7 天；超过期限后需联网确认授权才能使用。连接失效时进入 App 会提示登录，并在授权仍有效时提供“暂不登录”。禁用与授权超期均保留账本和待办；完全断网的手机在下次联网或原离线期限到期后执行限制。发布与迁移要求见 [部署说明](deploy/README.md)。

### 账本恢复与导出规则

- 使用欠款功能时，云端服务端与 App/网页需同时更新到支持负余额的版本；旧版本会拒绝读取或同步欠款账本。欠款账本应使用新版恢复。

- 充值赠送设置随账本同步、备份和快照保存。增量合并保留当前赠送设置；全量恢复采用备份设置，旧备份未含此设置时恢复为默认开启、10%。使用新赠送规则需同时更新云端和 App；旧设备未记录规则的待办仅在门店尚未保存新规则时兼容，规则变化后的充值需核对同步冲突。

- 增量合并优先按固定会员 ID 匹配，修改手机号后仍识别为同一会员。只有一份流水完整延续另一份时才同步余额、累计金额与撤销状态；两边都有独立交易或余额不一致时停止自动合并，需核对后选用完整账本恢复。
- 固定 ID 会为整份备份预留，不会因旧手机号被新会员复用而误认档案。较新流水会同步会员资料和注销状态；相同流水按档案更新时间同步资料，时间相同通常保留当前资料，改号并复用旧号时按固定 ID 对应的号码归属处理。相同流水中的注销状态会保留，较旧备份不能重新启用已注销会员。
- 已撤销标记必须存在对应冲正流水，否则备份预览和恢复都会拒绝。旧版备注中的原单号仍可用于还原撤销关联。
- CSV 对账明细会将可能被 Excel/WPS 解释为公式的姓名、电话、备注和流水单号加上文本前缀，原始账本及 JSON 备份保持原文；金额列仍以数值导出。
- 注销零余额会员会保留历史档案与流水，导出的备份仍可恢复。今日充值和消费统计排除已撤销原单。
- PC 批量导入按字段含义匹配表头，多个候选金额列需手动选择；预检前须确认姓名、手机号、本金与赠送金的列。金额最多两位小数，不接受指数写法或隐式舍入。归档会员不参与在用手机号匹配。
- PC 表格导入支持负余额：新会员先建零余额档案，再记录期初欠款流水；“累加余额”对已有会员记录对应扣款。负余额记录必须在预检后明确确认，赠送金仍须为非负数。
- PC 导入失败记录的修正表保留原始本金、赠送金及其他字段。格式错误的金额不会变成零，须修正后重新预检；会员和流水搜索、筛选或调整每页条数时会回到第一页。
- PC 财务操作在发送前保存原操作单号，导入任务同时保存各批次与进度。响应丢失、刷新或重新登录后，点击“继续确认待办”重试原任务；同一份数据和策略的已完成任务不会再次入账。存在未确认结果时，不能用新操作替代原单；服务器明确拒绝导入后可取消剩余部分，已经入库的记录保留。
- PC 导入历史按数据与策略的签名长期保存，云端在现有 `operations` 表内原子登记批次凭证；A→B→A、换设备或换同门店写入账号也不会重复入账。发布时须同步升级服务端和 PC 后台，无需新增数据库表或授权。部分入库后取消的整份文件禁止重开，请核对后仅导入剩余行；零入库取消可重试。升级会保留浏览器中最后一次旧完成任务，并为保留的旧待办补登记凭证；升级前已被覆盖的历史无法自动还原，旧文件再次导入前须先核对流水。
- 手机号在创建、编辑、导入及备份匹配中统一去除格式字符；旧流水和未编辑的历史档案保留原电话文本。旧账本若存在空号码或规范化后同号的多个在用档案，仍可查看、导出并按修改窗口显示的会员单号逐个修正，修正完成前禁止财务写入，不自动合并余额。导入预检遇到多个手机号候选会拒绝该行；外部 JSON 备份恢复继续严格拒绝冲突号码。
- PC 表格解析在独立 Worker 中执行，超过 10 秒可终止，切换文件或离开页面会取消解析。文件最多 10 MiB，数据最多 10,000 行（含表头前导共 10,005 物理行）、128 列、500,000 个范围单元格。ZIP 头信息和实际解压量会在解析前核对，总量最多 64 MiB，不支持 ZIP64 或分卷文件。单元格文本最多 4,096 个字符，展开后的数据预算为 10 MiB，重复引用共享字符串按每个单元格计入预算，在转换并发送 Worker 结果前检查。超限需缩小范围或分批导入。浏览器须支持 module Worker。
- 表头自动识别要求姓名与手机号分别位于不同列，可手动选择前 5 行中的表头；切换后须重新确认映射和预检。预检及失败修正表保留原文件的物理行号，包括标题行和空行。JSON 备份拒绝空白或重复的服务单号；旧版文本标签及文本标签数组仍可恢复、显示和导出，每个标签最多 128 个字符，数组最多 32 项。
- PC 财务 Excel 的金额列为数值单元格并显示两位小数，Excel/WPS 的 SUM 可直接汇总；姓名、手机号、备注仍按文本防公式注入规则导出。
- 移动端“已同步”需完成云端版本与完整性核验；核验进行中、失败或尚未确认会显示对应状态，失败保留最后成功时间。上传待办前先核验云端，服务端在账本事务锁内再次核验客户端已观察的版本和校验值。云端版本回退、同版本内容变化或完整性检查失败会持久保存冲突状态，暂停记账和自动同步，重启、退出或重新登录后仍须核对；本机账本和待办均保留。店主确认上传完整恢复账本时，会先逐批核对原待办并取消未提交操作，完成后再上传恢复结果；中断后点击“继续核对并上传恢复账本”。恢复上传响应丢失时用“立即同步”重试同一恢复操作。发布时须同步升级移动端和服务端，沿用现有数据库表。
- PC 原操作因其他设备改账而持续冲突时，可点击“核对并取消未入账操作”。服务器在账本锁内保留已入账操作、为未入账操作保存取消记录，迟到的原请求也不能再入账；核对响应丢失后继续确认会重试同一次核对。导入的已确认批次进度只累计一次；取消的批次须取消剩余导入并重新预检。此入口需同步升级服务端和 PC 网页，沿用现有数据库表。
- App 采用云端账本前会逐批核对原待办，保留已入账交易并取消未入账交易，包括初始迁移及完整恢复。全部核对并保存云端账本成功后才清空原待办；断网、存储失败或重启会保留原账本、操作单号与核对进度，期间暂停记账和自动同步。重新登录原账号后点击“继续核对并采用云端账本”。需同时更新 API 和 App，沿用现有数据库表。
- 手机和 PC 编辑会员时会核对打开窗口时的档案版本。后台同步、充值或注销改变档案后，旧表单不能直接保存；保留输入并提示重新打开窗口核对。
- App 充值及消费确认时重新核对姓名、手机号、余额和注销状态，资料变化需再次确认，欠款确认也会重置。PC 充值按服务端确认的对应流水播报实际余额、赠送及总到账金额；天猫精灵查询仅以未撤销消费计算上次到店日期。
- 网页根地址提供收银页面，`/admin/` 提供独立管理后台；两者共用在线账号与服务器账本，支持多个窗口。网页没有本机账本同步选择，原生 App 保留离线记账与同步冲突核对。
- APK 旧版本记录先在发布事务中处理，提交成功后才清理无数据库引用的安装包；发布提交失败保留旧文件，清理失败不影响已发布版本，重试发布同一版本可继续清理。
- PC 登录身份变化会清空账本缓存并重新加载，加载或提交失败会显示实际状态。充值、会员修改、服务保存和冲正均等待确认后关闭表单；充值冲正产生欠款时须核对撤销后余额并确认欠款。财务请求发送前会持久化结果未确认状态，页面在响应处理前刷新后，重试遇到限流或拒绝仍保留原操作单号。
- 网页版首次登录直接加载当前门店的云端账本，加载失败时不能记账；财务写入等待服务器确认，响应丢失时保留原操作单号供核对，避免重复入账。原生 App 保留未绑定时的本机模式，已登录只读账号仍不能修改本机账本。
- PC 充值档位的赠送金额按当前赠送比例计算，规则变化会同步更新展示；关闭赠送后不再展示赠送金额。
- PC 多窗口令牌刷新使用浏览器 Web Locks 协调，不支持 Web Locks 时使用 IndexedDB 锁；过期退出会先换取有效访问令牌再撤销会话。审计页支持逐页查看更早记录，“导出全部审计”会遍历完整门店历史，不受默认 100 条浏览页限制。
- PC 锁屏期限随会话保存并在多窗口共享，刷新令牌、重开页面和返回前台均不延长期限。超过 15 分钟无操作须验证密码解锁；升级前未记录期限的旧会话也须解锁一次，待确认财务操作继续保留。移动端撤销等待确认期间若余额或注销状态变化，会按最新状态再次确认后入账。
- 旧备份恢复的注销档案如果缺少手机号，撤销消费会在写入前拒绝重新启用；需先核对并恢复完整会员档案，避免产生无法读取的账本。
- 本地数据损坏时，应用仍提供备份恢复入口。全量恢复前保存当前原始文本，保存失败则不覆盖账本。
- 本地事务恢复日志损坏时，备份中心仍可导出原始账本及日志，并从有效备份全量恢复；采用云端账本也会先保留原始数据。替换写入失败或被系统终止时，旧账本及旧日志仍可恢复，不会直接清除损坏日志。
- 云端绑定设备损坏后，店主可离线全量恢复备份，原待办与原始文本仍会保留。恢复后先在云端设置中导出核对，再联网选择采用云端账本或确认上传恢复结果。账号降权和初始迁移冲突也提供同一核对入口。
- 安卓导出先通过 Filesystem 写入应用缓存，再通过 Share 调用系统分享面板，供微信或文件管理器接收。缓存不等于长期外部备份；请确认接收端文件可打开并另存。浏览器版通过下载记录核对保存结果。
- 手动快照写入失败会显示失败；外部导出不依赖快照成功。恢复已完成但后续快照失败时，会提示立即导出备份。

## 🚀 如何获取并安装 `.apk` 安装包？

### 方式 A：云端自动打包（最省电脑、推荐 ⭐⭐⭐⭐⭐）
首次发布前需要创建一份长期使用的 Android release keystore，并将其配置为 GitHub 仓库 Actions secrets。此后 GitHub Actions 使用同一密钥构建 release APK：

遇到 `Missing SIGNING_KEYSTORE_BASE64` 时，按 [GitHub APK 签名配置指南](deploy/github-apk.md)完成配置。工作流固定使用 Ubuntu 24.04、Node.js 22 和 Java 21，Actions 自身使用 Node.js 24，避免旧 Actions 的运行时弃用提示及 ubuntu-latest 迁移影响。

1. 将当前项目推送至您自己的 GitHub 仓库；
2. 在安全设备上只创建一次签名密钥，并至少离线保存两份 keystore 备份。密钥一旦丢失，后续 APK 将无法覆盖安装到当前版本；不要把 keystore 或密码提交到 Git；
3. 在 GitHub 仓库 **Settings → Secrets and variables → Actions** 设置 secrets：`SIGNING_KEYSTORE_BASE64`、`RELEASE_STORE_PASSWORD`、`RELEASE_KEY_ALIAS`、`RELEASE_KEY_PASSWORD`；再设置变量 `RELEASE_CERT_SHA256` 为该别名证书的 SHA-256 指纹；`SIGNING_KEYSTORE_BASE64` 是 keystore 文件的 Base64 内容；
4. 推送至 `main`/`master` 或手动运行 Actions。工作流会运行测试、使用同一签名构建 release APK，并验证签名；缺少密钥时会失败，不会提供 debug APK；
5. 下载 Actions 产物 `member-manager-v*.apk` 安装。以后不要更换 keystore、别名或密码，也不要重命名 `.github/workflows/build-apk.yml`（版本序号按该工作流递增）。

生成 keystore 的示例命令（请替换别名，并自行安全保管输入的密码）：

```sh
keytool -genkeypair -v -keystore hairstudio-release.jks -alias hairstudio-release -keyalg RSA -keysize 4096 -validity 10000
```

PowerShell 可用以下命令生成要填入 `SIGNING_KEYSTORE_BASE64` 的单行值：

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes(".\hairstudio-release.jks"))
```

查看并记录证书指纹（不要在后续版本更换）：

```sh
keytool -list -v -keystore hairstudio-release.jks -alias hairstudio-release
```

将输出中的 `SHA256` 指纹填入 `RELEASE_CERT_SHA256`。CI 会逐次比对 APK 的实际签名证书与该指纹；密钥被误换时构建会失败。

### 持续升级与账本保护

- `capacitor.config.json` 的 `appId` 是 Android 包名的唯一来源。保持它不变、保持同一 release keystore，并安装更高 `versionCode` 的 APK，Android 才会按应用内升级处理并保留沙盒数据。
- 多键账本写入先落恢复日志；应用若在写入过程中被系统终止，下次启动会先恢复旧数据。若设备空间不足以保存恢复点，操作会在修改账本前失败。
- 更新前仍应通过应用内“备份全部账本”导出 JSON，尤其是跨手机迁移、卸载重装或切换首次固定签名版本时。卸载/清除应用数据不属于原位升级，应用无法保证本地账本仍存在。
- 旧版 Actions 产物是 runner 临时签名的 debug APK，无法与新固定签名版本直接覆盖安装。切换时先在旧版导出 JSON，再安装首次固定签名版本并导入备份；之后的版本才可直接升级。

### 方式 B：本地 Android Studio 导出（如有开发机）
1. 在电脑上运行 `npm run build`；
2. 使用 Android Studio 打开项目中的 `android` 目录；
3. 配置 `RELEASE_STORE_FILE`、`RELEASE_STORE_PASSWORD`、`RELEASE_KEY_ALIAS`、`RELEASE_KEY_PASSWORD` 和递增的 `VERSION_CODE` 环境变量；
4. 运行 `gradlew assembleRelease`。没有有效签名配置时，release 构建会失败。

### 依赖维护

执行 `npm run clean` 可清理 `tmp/`、`output/`、前后端 `dist/`、Vite 与 Android 构建缓存。临时脚本和验证日志放在 `tmp/` 或 `output/`，两者均不进入 Git 和 Docker 构建上下文。此命令保留依赖、源码、配置、签名密钥及 `releases/`、`backups/`；清理后按需运行 `npm run build:web`、`npm run admin:build` 或 `npm run build` 重新构建。

`package.json` 仅对 Capacitor CLI → rimraf → glob 设置 `^14.0.3` 覆盖，修复 glob/minimatch 的已知资源耗尽漏洞，保持 Capacitor 7 和 Node.js 22 构建兼容。测试用 `csv-parse` 已升级到修复原型替换漏洞的 7.0.3。更新依赖时运行 `npm ci`、`npm test`、`npm run build` 和 `npm audit --registry=https://registry.npmjs.org`；上游采用安全版本后可以移除此覆盖。
