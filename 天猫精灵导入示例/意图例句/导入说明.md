## 先配置实体和参数，再导入语料

CSV 中的参数列是语料标注，不是意图参数和实体的配置文件。模板语料要求先手动创建参数；不要依赖导入 CSV 自动创建参数。此前说明没有充分强调这个前提。

1. 在“语音交互模型 → 实体”中创建或复用会员实体。新建时可命名为“会员标识”，标识为 member_entity，补充训练用的会员姓名、手机尾号和完整手机号，例如张三、李四、王五、1234、5678、13800001234。实际识别范围取决于实体配置和模型效果；CSV 中列出的会员不会自动成为系统中的会员。
2. 在实体列表中引用公共实体 sys.price，供金额参数使用。它表示带货币单位的金额，例如 200元、200.50元、两百元、50块钱。本文件已经把“王五充值100”修正为“王五充值100元”，对应 amount 为“100元”。
3. 在实体列表中创建或复用“服务项目”自定义实体，例如标识 service_entity，填写门店实际服务名称及对应说法。消费例句中使用了“洗剪吹”“剪发”“理发”，应在实体中补齐这些值或其对应的同义词；只把实际属于同一项目的说法归为同义词。然后打开对应意图的“编辑 → 参数 → 添加”，分别建立以下参数并关联实体。参数名称及大小写必须与 CSV 表头和模板占位符一致。

| 意图 | 参数名称 | 关联实体 |
| --- | --- | --- |
| DefaultWelcomeIntent | 无 | 无 |
| QueryMemberIntent | memberQuery | 会员实体，例如 member_entity |
| RechargeIntent | memberQuery | 会员实体，例如 member_entity |
| RechargeIntent | amount | sys.price |
| ConsumeIntent | memberQuery | 会员实体，例如 member_entity |
| ConsumeIntent | amount | sys.price |
| ConsumeIntent | service | 服务项目实体，例如 service_entity；非必填 |

4. 保存实体和参数后，在每个对应意图的用户表达/语料页面导入自己的 CSV 文件。已经导入但没有参数的意图，应先补齐参数，再核对已有标注或重新导入，避免重复语料。不要给会员或金额设置虚构的默认值。
5. 检查具体例句的词段绑定：“李四充值200元”中，“李四”对应 memberQuery，“200元”对应 amount，“充值”是普通文本。“张三洗剪吹扣款38元”中，“张三”对应 memberQuery，“洗剪吹”对应 service，“38元”对应 amount，“扣款”是普通文本。消费文件的列顺序为 dialog、memberQuery、amount、service；49 条语料中，具体例句 24 条、模板 25 条，服务词段已标注，带服务的模板使用 @{service}。模板的参数值列均留空，与原始示例一致。
6. 服务是消费意图的第三个参数。像“王五扣款25元”这样没说服务的具体例句，service 列留空；没有服务的模板不含 @{service}。为兼容这些表达，平台中将 service 设置为非必填，不要填入虚构的服务默认值。后端已经支持 service，无需为新增语料列改接口。
7. 参数高亮颜色相同不能单独证明绑定错误。充值意图应有 memberQuery、amount 两项，消费意图应有 memberQuery、amount、service 三项；分别点击各词段确认绑定名称。如果没有标注，可在具体例句中选中相应原文并关联正确的参数和实体。
8. 保存并执行平台提供的训练/构建，再使用更新后的模型测试。检查 RechargeIntent 返回 memberQuery:李四、amount:200元，ConsumeIntent 返回 memberQuery:张三、service:洗剪吹、amount:38元；实体归一化后的具体返回格式以平台测试结果为准。

查询补充覆盖“查询苏新用户”“查询用户苏新”“查询苏新”等表达，memberQuery 只标注“苏新”，“查询”“用户”不属于会员标识。消费补充覆盖“苏新消费100元”“苏新消费一百元”等表达，memberQuery=苏新、amount=100元或一百元，未说项目时 service 为空。金额仍关联 sys.price，service 非必选。

导入后仍需把真实会员姓名补进 memberQuery 的会员实体，并保存、构建模型。“某某”代表实际姓名，不需要录入字面上的“某某”。如果把 memberQuery 改成了 sys.select，请先恢复会员自定义实体；当前后端没有返回 SELECT/candidateList 的动态选择流程，直接换实体不会让任意姓名透传。

平台文字测试先核对“查询苏新用户”进入 QueryMemberIntent、memberQuery=苏新；“苏新消费100元”进入 ConsumeIntent、memberQuery=苏新、amount=100元。欢迎后等自动开麦再说完整句。真机出现算数回复时，查看 App 的识别原文：姓名或“消费”识别错误需要核对姓名写法、实体同义词和发音；原文正确而意图未命中需要检查导入标注、模型构建和真机测试配置。网页测试参数正确不能证明真机路由已通过。

本批文件中的张三、李四等是示例，不能代替门店真实会员实体。实际要用“苏新消费一百元”，须核对会员实体包含“苏新”，ConsumeIntent 中有 `@{memberQuery}消费@{amount}` 模板并正确关联参数。所有已录入会员实体的姓名可以复用该模板，无需为每个会员重复创建整句例句。常用的“苏新消费一百元”“苏新充值两百元”“查询苏新余额”可作为辅助例句；各句只放在对应意图中。实际手机号或尾号同样要加入当前会员实体，不能把金额数字或不同会员的尾号映射到同一个姓名。

### 只有例句里的名字能识别

句式和姓名的识别范围是两项配置。语料中的 `@{memberQuery}` 表示用该参数关联实体里的取值替换姓名，不代表任意姓名均可输入。官方说明：没有绑定参数的语料需要匹配固定文字；即使符合语料规则，如果关键词不在参数关联实体内，也可能无法识别意图。给例句划词绑定参数时，标注的词会自动加入关联实体，这也解释了为什么例句里的张三能用、其他姓名不能用。

排查时先打开 ConsumeIntent 的 memberQuery，确认关联的是会员自定义实体；查询和充值应复用同一个实体。在该实体添加一个真实姓名，保存并构建模型，保留已有消费/查询模板，再测试这个姓名的完整指令。这个验证无需为该姓名新增整句例句。后台会员数据不会持续自动同步到平台实体，新增会员后仍需维护实体值；sys.select 是动态候选选择实体，当前不能代替任意姓名识别。

官方依据：[语料、参数绑定及实体值范围](https://www.aligenie.com/doc/20255408/amm8fg)、[实体配置](https://www.aligenie.com/doc/20255408/qyq166)。

### 完整句仍被追问金额和会员

如果“张三消费一百元”返回 ConsumeIntent、参数 null，回答“一百元”后仍是 ConsumeIntent、只有 amount，最后回答“张三”才补齐 memberQuery，说明意图没有切换，而是首轮两个参数都未抽出。平台会按必选参数逐个追问，自动追问时不调用后端。

在 ConsumeIntent 中手工核对一条具体例句“张三消费一百元”：划词“张三”绑定 memberQuery，“一百元”整段绑定 amount，“消费”保留普通文字。同时确认 `@{memberQuery}消费@{amount}` 是单轮对话模板，不是只放在追问回复里；memberQuery 关联会员实体，amount 关联 sys.price，service 非必选，没有额外的必选金额或会员参数。保存并构建模型后，先检查第一轮即返回 memberQuery=张三、amount=一百元，再测试追问。

消费追问的文案和回复应分别归属于本意图的参数：memberQuery 可问“请说扣款会员姓名或手机尾号”，回复模板 `@{memberQuery}`、`尾号@{memberQuery}`；amount 可问“请说消费金额，例如一百元”，回复模板 `@{amount}`、`消费@{amount}`。会员实体应包含实际姓名；“苏新”和“舒心”是不同写法，只有核对同一会员后才配置同义词，不能把任意同音姓名直接对应到同一个账号。

后端现已兼容 sys.price 的人民币 JSON 归一化结果，并增加诊断日志；更新 API 后生效。网页测试没有设备/用户标识的限制保持不变。查看日志和只读授权方法见 [语音服务说明](../../deploy/voice-integration.md)。

memberQuery 和 amount 的必选设置只在已识别对应意图后起作用。如果要追问，参数下应同时配置“精灵追问”和“用户可能回复”，会员可填 `@{memberQuery}`、`尾号@{memberQuery}`，金额可填 `@{amount}`、`消费@{amount}`、`充值@{amount}`。金额回答用“一百元”，避免只说“一百”与会员数字混淆。

技能呼叫名改成“顾客”后，可以先唤起“打开顾客”，等欢迎后自动开麦再说“查询苏新余额”或“苏新消费一百元”。欢迎后单独说“幺七三零八四零”并不对应业务意图；只有在已经追问 memberQuery 时才单独报会员标识。系统回答字的笔顺或充话费，表示该轮已经跳出技能，不能据此判断会员查询或记账接口成功。保存、构建语音模型并开启真机测试后，才在已绑定音箱验证完整句、参数追问和“是的/不是”的确认流程。

官方操作说明：[添加参数](https://www.aligenie.com/doc/20255408/sgmvp9)、[语料与模板参数](https://www.aligenie.com/doc/20255408/amm8fg)、[实体与公共金额实体](https://www.aligenie.com/doc/20255408/qyq166)。

如果 DefaultWelcomeIntent 的编辑页不提供语料导入入口，保留默认欢迎意图，并在技能呼叫名/唤醒配置中使用“梦飞管家”；其余三个业务意图分别导入对应文件。

可先测试“梦飞管家”“查询尾号1234余额”“李四充值200元”“张三洗剪吹扣款38元”。网页在线测试用于验证意图和参数识别；真实记账仍需已绑定音箱的真机测试。
